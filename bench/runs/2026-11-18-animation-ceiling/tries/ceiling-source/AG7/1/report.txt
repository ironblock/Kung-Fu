I read the source and wrote the four answers from how the code behaves. Nothing was run. The scene's tick path skips any group that has a manager (`tickAnimationImpl` checks `_animationManager`), so an attached clip is advanced only by `updateAnimationManager`. That gives 0.25 s after one frame, with no double advance. An unattached sibling is still advanced by the scene. After `removeAnimationGroup`, the task's dispose hook clears `_animationManager`, so the scene advances the clip again.

I'm not certain of the 0.25 figure: the controller's `tick` lives in `skeleton-updater`, which wasn't provided. I assumed it adds `deltaMs/1000 * speedRatio` to `time` and wraps within the 4 s loop. I also assumed the manager has `fixedDeltaMs` 0, the default, and that the clip is playing and not stopped.
