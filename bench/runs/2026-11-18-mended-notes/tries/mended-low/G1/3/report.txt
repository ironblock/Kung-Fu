I wrote `src/mode-limits.ts` which copies all fields from the mode's limits object into the camera's existing `limits` object in place (because per note 39, assigning a new object to `camera.limits` is never used by the camera's clamps), then calls `setGeospatialOrientation(camera, {})` to immediately re-apply the clamps to the current pose so the camera is within the new mode's bounds right away. I was not sure whether `setGeospatialOrientation` with an empty object could ever fail or have side effects beyond re-clamping (the notes say it keeps current values for omitted fields and re-applies limits), but based on the documented behavior it should be safe.
