I wrote `src/screen-shift.ts` which snapshots the camera's view/view-projection matrices (copied, since the library returns its internal cache per note 37), the resolved pixel viewport, canvas dimensions, and — when `_useFloatingOrigin` is set — the camera's world position as `worldOrigin` (note 67). `shift` reprojects the point under both the stored and current snapshots via `projectWorldToScreen` and returns the difference in `cssX`/`cssY`.

The one thing I was not fully sure of: whether `Mat4` in this build is guaranteed to be a `Float32Array` (vs. a plain `number[]`). I used `Float32Array.from()` which handles both, and `projectWorldToScreen` accepts it either way, so it should be safe — but if the library's `Mat4` is a struct-of-structs or some other layout, the copy would need adjusting.
