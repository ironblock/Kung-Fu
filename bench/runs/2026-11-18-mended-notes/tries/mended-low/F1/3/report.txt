I used `attachConfigurableFreeControl` with `fastMultiplier: 20` and `fastKeys` listing every movement key (WASD, arrows, Space/PageUp, Shift/PageDown), which makes each held movement key travel 20× the default per-frame distance while leaving `camera.speed` untouched—so the mouse-look inertia threshold (which is `speed * 0.001`) and the drag-to-look behavior are unchanged. The returned dispose function is the one `attachConfigurableFreeControl` gives back, so it removes all canvas listeners and stops the per-frame step.

I was not sure whether `fastMultiplier` also scales the inertia decay of the *movement* velocity (as opposed to only the per-frame input), but the notes only document the per-frame addition (`speed * max(deltaMs,1) / sqrt(100000)`) and the separate look-inertia threshold, so I assumed the multiplier applies to the input step only, which is consistent with the name and note 18.
