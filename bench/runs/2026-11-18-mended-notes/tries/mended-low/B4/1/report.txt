I disabled the radius-based pitch constraint by setting `limits.pitchDisabledRadiusScale` to `null` on the existing limits object (note 39: in-place edits apply at the next value-changing write), then wrote the desired pitch — which triggers that update and stores the tilt free of the radius clamp. This works at the initial fully-zoomed-out radius (4R) where pitch would otherwise be forced to 0.001, and the tilt persists through later zoom changes because the constraint is gone.

I was not sure of one thing: whether some external code path (e.g. a future `setGeospatialOrientation` call from the app) might re-assign a fresh `limits` object, which per note 39 would never be used by the camera's clamps — but that would actually be in our favour (the old limits with null scale would still govern), so I believe the solution is robust either way.
