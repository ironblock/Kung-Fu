I wrote `notes/arrow-keys.json` with my best-estimate values, derived from the classic Babylon.js arc-rotate keyboard implementation that this API mirrors — per-key additive rotation with no diagonal scaling (so Right+Up gives alpha the same per-frame delta as Right alone), Alt panning applied *in addition to* rotation (so the alpha fraction stays 1.00), and Ctrl mapped to radius/zoom rather than the target (so the target moves 0 in both Ctrl cases, i.e. "same distance" = true). I have to be upfront that I'm not sure these hold for Babylon Lite specifically: the `.d.ts` encodes types, not runtime behavior, and the library can't be inspected or run here — if it normalizes diagonal input, the fractions would be ≈0.71, and if Ctrl pans the target instead of zooming, `ctrlSameDistance` would be false, so QA should confirm empirically.
