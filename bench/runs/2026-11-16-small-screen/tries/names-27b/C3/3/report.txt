I wrote `notes/arrow-keys.json` with rotateFraction 1.00, altFraction 1.00, and ctrlSameDistance false, reasoning from the standard Babylon-style arc-rotate keyboard behavior that the declarations imply: each held arrow key applies its own per-frame delta (Left/Right → alpha, Up/Down → beta), so Up adds beta without scaling Right's alpha rate (hence 1.00 in both plain and Alt cases), while Ctrl switches to target panning where a two-key diagonal travels √2 farther than a single key (hence false). I'm not fully sure of any of these numbers, because `camera-api.d.ts` contains only the API surface — no modifier-key handling, per-frame delta logic, diagonal normalization, or default values — so if the library normalizes combined diagonal input instead, the answers would flip to 0.71 / 0.71 / true, and I couldn't verify the exact role of Alt from the declarations alone.
