I read `camera-api.d.ts` and `camera-notes.md`, then wrote `notes/tighter-zoom.json` with the four results: per note 37 the limits change is not applied by itself (`asIs` stays 4000) and a no-change radius write doesn't count as a value-changing write (`radiusSelf` stays 4000), while any center assignment — even `cam.center = cam.center` — applies it (`centerSelf` 2000), and `setGeospatialOrientation(camera, {})` re-applies the full orientation through `_setOrientation`, which clamps radius against the current limits (`emptyOrientation` 2000). The one thing I was less sure of is `emptyOrientation`: the notes never state it explicitly, so I inferred it from note 11 (setGeospatialOrientation re-orbits at once, i.e. goes through `_setOrientation`) and note 7 (it applies radius and pitch together, filling omitted fields from the camera) — if the library no-ops a fully-omitted orientation, that one would be 4000 instead.
