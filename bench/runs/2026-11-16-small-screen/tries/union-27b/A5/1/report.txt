I applied note 13's rules: the normalized viewport spans x 800–1100 px and (counting y from the bottom) 50–200 px from the bottom, so `resolveCameraViewport` returns x 800, y 300 (from the top), width 200 after clamping the 100 px that overhangs the right edge, height 150, and I wrote that plus the aspect to `notes/inset-slide.json`. Since the aspect (200/150 ≈ 1.33) is the aspect of the same clamped rect the frame is placed on, the frame and the picture will line up during the slide — no different animation needed, as long as the inset is drawn with that clamped aspect.

The one thing I was not sure of: the notes never state explicitly whether `getEffectiveAspectRatio` clamps to the canvas edges or uses the raw viewport dimensions — I inferred from note 36 ("match what is rendered") that it uses the clamped rect, giving 1.33; if it instead used the unclamped 300×150, it would return 2.0, and the picture would not match the frame.
