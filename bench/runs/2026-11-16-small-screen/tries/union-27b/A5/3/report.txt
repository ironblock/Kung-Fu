I wrote `notes/inset-slide.json` with the pixel viewport and effective aspect computed from the halfway-slide camera: raw viewport is 800→1100 × 300→450 px (y flipped from bottom, per note 13), so `resolveCameraViewport` clamps the width to 200, and `getEffectiveAspectRatio` is (0.3·1000)/(0.3·500) = 2.00 — which won't line up with the 200×150 frame (aspect 1.33), so the inset picture and frame will mismatch during the slide unless you animate or size the inset differently. The one thing I wasn't sure of: I assumed `getEffectiveAspectRatio` uses the raw, unclamped viewport fractions (standard Babylon behavior, since the notes only document clamping for `resolveCameraViewport`); if it clamps to the canvas instead, the aspect would be 200/150 ≈ 1.33.
