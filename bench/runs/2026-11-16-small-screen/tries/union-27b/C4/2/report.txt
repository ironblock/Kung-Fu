I wrote `src/turntable.ts`, which chains `interpolateArcRotateCamera` calls (each awaited before the next starts) into sub-half-turn segments, because the interpolator's shortest-arc-mod-2π rule would otherwise reverse direction for fractional turns or snap on the first frame for whole turns; each segment uses the library's default easing, ends exactly on its goal, and only `alpha` is in the goal, so radius, beta and target stay put and the promise resolves with `alpha` at start + 2π·turns. I was not fully sure that `interpolateArcRotateCamera` is exported from the `@babylonjs/lite` package root (I imported it there to match your type imports), and if the camera has alpha limits set, the interpolator clamps its goals so the final alpha would land on the limit rather than start + 2π·turns — I did not touch limits, and I throw a `RangeError` for negative or non-finite `turns` rather than silently no-op.
