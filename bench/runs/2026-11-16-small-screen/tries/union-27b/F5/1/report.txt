I read the camera type declarations and notes, then wrote the four answers to `notes/pointer-lock.json`. The free-camera control only turns the camera while a drag is active (buttons 0/1/2), so button-less motion never turns it, and per note 66 it has no pointer-lock handling — so while locked it reads the frozen `clientX`/`clientY` rather than `movementX`/`movementY`, and a held-button drag produces no delta; right-drag (button 2) and a one-finger touch (button 0) both start a drag, so they turn.

The one thing I'm not fully certain of is `lockedButtonHeld`: I inferred the control uses `clientX`/`clientY` deltas from note 66 ("there is no pointer lock"), but the declarations don't pin down the exact coordinate source — if it actually read `movementX`/`movementY`, that answer would flip to `true`.
