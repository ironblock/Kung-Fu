I wrote `src/label-position.ts`, which projects the point through the camera's own view/view-projection caches using `projectWorldToScreen` (with the backing-store aspect from `getEffectiveAspectRatio`, the picture region from `resolveCameraViewport`, CSS-pixel scaling via `cssWidth`/`cssHeight`, and `worldOrigin` when `camera._useFloatingOrigin` is set), returning unclamped `cssX`/`cssY` and treating `visible` as "not behind the camera and not offscreen" so that points past the far plane still count.

I'm not fully sure of two things: (1) that `projectWorldToScreen`, `resolveCameraViewport`, `getViewMatrix`, `getViewProjectionMatrix`, `getEffectiveAspectRatio` and `getCameraPosition` are all re-exported from the `@babylonjs/lite` package root — the declarations show them in the camera module files, but I couldn't check the package index; and (2) the exact boundary of the library's `behindCamera` flag — I'm assuming it means "behind the eye," so a point between the eye and the near plane would come back visible if it lands in frame, which matches "in front of the camera" as I read it.
