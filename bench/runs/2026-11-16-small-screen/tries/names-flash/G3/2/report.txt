I added `app/src/fly-to-place.ts` and made it wrap `flyGeospatialCameraToAsync`, tracking one active flight per camera so newer fly-to calls resolve older ones as `false`; it also temporarily watches `camera._cancelFly` so cancellations from elsewhere can resolve `false` without waiting for the library fly promise, and it verifies the final camera orientation before returning `true`. I was not sure whether `_cancelFly` is guaranteed to be called for every fly-to cancellation in this library version, and whether plain `{x,y,z}` center objects are accepted as `Vec3` at runtime, so the code defensively checks arrival and uses a small tolerance.
