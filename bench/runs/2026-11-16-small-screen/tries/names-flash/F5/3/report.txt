I created `app/notes/pointer-lock.json` with my best inference from the declarations: the usual free-camera controls likely require a primary pointer/touch drag and use relative pointer movement, so pointer lock without a button would not turn the camera, while left-button held, touch drag, and not right drag are likely. I was not fully sure because the `.d.ts` files only describe the API and do not document the runtime event handling, such as whether controls use `movementX/Y` versus `clientX/Y` deltas or whether the right button is deliberately ignored.
