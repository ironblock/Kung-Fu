I wrote the answer to `/home/dev/da727f/app/notes/pointer-lock.json`: `lockedNoButton` false, `lockedButtonHeld` false, `rightDrag` true, `touchDrag` true. The first two come from the notes: a free-camera drag only starts with button 0, 1 or 2, and the camera only moves when you pass a scene, which you do. Note 33 covers right-drag turning. I'm not sure of the other two. The notes don't say whether the drag reads `clientX` or `movementX`, so `lockedButtonHeld` is a guess that assumes `clientX`, under which the camera wouldn't turn while locked. If the library uses `movementX`, that value flips to true. `touchDrag` assumes touch contacts report button 0 and that the library's touch CSS doesn't block the drag. Neither is confirmed, and I couldn't check the library source.
