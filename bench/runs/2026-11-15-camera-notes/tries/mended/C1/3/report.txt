I wrote `src/steady-zoom.ts` in `/home/dev/e7280c/app`. It calls the library's `attachControl` for drag, pan and pinch, and replaces only the wheel. The wheel listener is registered before `attachControl`, so it runs first and stops the library's wheel handler. It then moves `radius` by a fixed amount per unit of `deltaY`, using the radius, `wheelPrecision` and `inertia` read at call time. The returned function calls the library's disposer and removes the wheel listener.

I could not run or type-check this, since the library isn't on the machine. Things I'm not sure of:
- I assumed `attachControl` is exported from the `@babylonjs/lite` root. The declarations only show it in an internal module.
- The library's wheel listener is assumed to be on the canvas. If it is on `window` in the capture phase, it will still zoom by radius.
- `stopImmediatePropagation` also blocks any other wheel listeners on the canvas.
- The zoom is applied instantly rather than eased, so the library's wheel coasting is lost.
- The distance scales with `deltaY`, as the library's does. If you want exactly one fixed step per notch regardless of `deltaY`, that is a small change.
- If `inertia` is 1 or more, the default distance is undefined, so I treat the coast factor as 1.
