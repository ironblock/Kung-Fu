I wrote `notes/arrow-keys.json` with `rotateFraction` 0.71, `altFraction` 1.00 and `ctrlSameDistance` true. I did not run anything, since the library isn't on this machine. The answers come from note 35 in `camera-notes.md`, which says arrows rotate at 1/100 per frame with diagonals normalized, and Ctrl+arrows pan at 1/50 under the same normalization.

I'm not confident in these values:
- The only source is that secondhand note. The `.d.ts` has no keyboard implementation, so I couldn't check the normalization or the Alt behaviour.
- `altFraction` of 1.00 assumes Up under Alt only zooms and doesn't touch alpha, and that the normalization doesn't apply across rotate and zoom. The notes don't say how fast Alt+Left/Right rotates, so I assumed it matches the plain arrow rate.
- Note 17 says `keyboard: true` does nothing unless `enableArcRotateKeyboardControls()` is called before `attachControl`. If that call is missing in the app, all three results would be zero or meaningless, so check it first.
- Note 51 says the arrow listeners sit on the canvas and need focus, so a QA or test harness has to focus the canvas.
