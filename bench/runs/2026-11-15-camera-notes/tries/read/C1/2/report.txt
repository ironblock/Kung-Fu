I wrote `src/steady-zoom.ts` in `/home/dev/6aef70/app/src/`. It calls the library's `attachControl` with the scene, so drag, pan and pinch are unchanged. For wheel events that reach the canvas, a window capture listener temporarily scales `camera.wheelPrecision` by `radius / baseRadius`, where the base values are read at call time. The library's step is `deltaY * radius / (wheelPrecision * 1000)`, so each notch now moves the same distance no matter where the camera has gone since. A bubble listener restores the original value, and the returned function removes both window listeners and calls the `attachControl` cleanup. Nothing runs per frame.

I could not run or type-check this, because the library isn't installed. Things I'm not sure of:
- I import `attachControl` from the package root. The declarations are in `arc-rotate-controls.d.ts`, but I don't know whether the root re-exports it.
- The wheel formula comes from your notes (item 18), not from the library source. I also assumed the library's wheel handler is on the canvas, not on the window or document. If it is elsewhere, the capture-then-bubble ordering would not hold.
- If a radius limit clamps a notch, that notch will be shorter. Also, if something stops propagation of the wheel event before it reaches the window bubble listener, `wheelPrecision` stays altered until the next wheel event or the cleanup restores it.
