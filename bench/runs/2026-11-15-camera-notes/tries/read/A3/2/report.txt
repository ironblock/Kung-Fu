I wrote `app/src/screen-shift.ts`. `mark()` and the constructor copy the camera's view matrix, view-projection matrix, viewport and canvas size. `shift()` projects the point with that saved state and with the camera's current state, then returns the difference in CSS pixels. The field of view is part of the projection, so zooming by FOV is measured too. I could not compile or run it, because `@babylonjs/lite` is not on this machine and `tsconfig.json` points at a missing `../babylon-lite` path.

Things I'm not sure of:
- I assumed `getViewMatrix`, `getViewProjectionMatrix`, `getCameraPosition`, `getEffectiveAspectRatio`, `resolveCameraViewport` and `projectWorldToScreen` are exported from the package root. The `.d.ts` files only show them in their modules.
- Matrices are copied with `structuredClone` so I don't need to know whether `Mat4` is a typed array or a plain array.
- Each snapshot uses the canvas size from its own moment, so a canvas resize between mark and shift shows up as movement. If you want only camera motion, that needs a change.
- Points behind the camera give NaN, as the notes describe. Your points are in front, so I left that alone.
- Your note 3 says assigning `camera.target = {...}` may not update the view until alpha, beta or radius changes. That would make `shift` read the same stale view the renderer uses, so I didn't work around it.
