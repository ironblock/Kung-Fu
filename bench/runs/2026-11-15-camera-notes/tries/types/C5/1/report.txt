I wrote `notes/same-frame.json` with `rejects: true`, `finalRadius: 7`, `finalTargetX: 0`. Per the declarations, `spot.x = 5` is safe because the goal's `target` is copied at call time, but `camera.radius = 7` is a direct pose write between frames, which cancels the transition and rejects `done`, so that line needs to move before the call if you want the animation to finish. I could not run the library, so the rejection answer and the final numbers are my reading of the doc comment on `interpolateArcRotateCamera`, not observed behavior. The doc doesn't say whether the pose baseline is captured at call time or at the first frame. If it is captured at the first frame, the write wouldn't count and the result would be `rejects: false`, with the camera ending at radius 7 and target x 5. Also, `done` is not caught in `showSpot()`, so a rejection will show up as an unhandled promise rejection.
