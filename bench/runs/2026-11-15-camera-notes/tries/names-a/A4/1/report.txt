I wrote the answer to `/home/dev/7b642b/app/notes/over-the-top.json`, the only file I changed. The answers are inferred, not verified: the `.d.ts` file only declares the camera API and the library source isn't on this machine. I assumed the standard arc-rotate formula (position = target + r·(cos α·sin β, cos β, sin α·sin β), with a world-up lookAt and no clamping because no beta limits are set). With that, `beta = -0.5` puts the eye at (−4.794, 8.776, 0), which is the same point as a fresh camera at `alpha = π, beta = 0.5`, and the picture stays upright. The biggest thing I couldn't check is whether this library clamps beta when it is set directly or when the view matrix is built. If it does, the eye would land near (0, 10, 0) and the other values would change, so please confirm against the library before relying on this.
