I wrote `app/notes/over-the-top.json` with `eyeX` -4.794, `eyeY` 8.776, `upright` true, and `sameAsOtherSide` true. These are inferred, not verified. The type declarations give the camera's fields and signatures but not how `beta` maps to position or view, and I don't have the implementation to check. I assumed the common arc-rotate convention, where the eye is `target + r·(cos α·sin β, cos β, sin α·sin β)` and the up vector is world +Y. Under that convention, `beta = -0.5` puts the eye on the same side at the same height as `alpha = π, beta = 0.5`, so the two views match, though only up to floating-point rounding.

The two things I'd check before relying on this are whether the library clamps `beta` or flips the up vector when it goes negative, and whether `worldMatrix` or the position only updates once a frame is rendered. In the second case, `eyeX` and `eyeY` would still show the old position, (4.794, 8.776). I couldn't run the library to tell which applies.
