I wrote `/home/dev/e1a196/app/src/spin-around.ts`. On each frame of the scene's render loop it sets `yaw` to the start heading plus a full turn times an eased progress value. Progress only ever goes up, so the heading always moves toward increasing yaw. On the last frame it writes back the exact heading it started with. It never writes the centre, the tilt or the zoom. Nothing has been compiled or run, since the library isn't on this machine.

Things I wasn't sure of:
- **Render-loop hook:** the declarations you have don't include `SceneContext`, so I don't know the public way to run code every frame. I used `scene._beforeRender`, which note 1 says the library's own controls use. It's internal and I'm guessing its exact shape. If the scene doesn't have it, the promise rejects with a clear error rather than switching to a different timer. If you know the proper hook, it's a one-line change.
- **Interruptions (my choice):** if something else changes the heading mid-spin, such as a right-drag, a double-click fly or a second spin, the spin stops where it is and the promise resolves early. That's how the library's own fly behaves. Otherwise it would fight the user's drag for up to 10 seconds. Panning and zooming don't stop it.
- **Pauses:** each frame counts at most 100 ms toward the duration. A stalled loop or a hidden tab makes the spin carry on later instead of jumping to the end.
- **Yaw limits:** if `camera.limits.yawMin`/`yawMax` are set to less than a full circle, the camera will cut the turn short, and I didn't handle that. The defaults aren't documented, but note 41 suggests they allow a full turn.
