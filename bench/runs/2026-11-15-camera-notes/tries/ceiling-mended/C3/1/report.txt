I wrote `/home/dev/f2381e/app/notes/arrow-keys.json` with `{ "rotateFraction": 0.71, "altFraction": 0.71, "ctrlSameDistance": true }`, working from note 28 in `camera-notes.md`. With two arrows held, each key gets 0.01/√2 per frame instead of 0.01, so `alpha` turns 1/√2 ≈ 0.71 as far. Inertia scales both cases the same way, so the fraction holds at any frame count. With Ctrl, the two pan directions are at right angles, so two components of 1/√2 still add up to the same total distance.

One thing I'm not sure of: the note doesn't say whether the split still applies when one of the keys is zooming (Alt+Up) or both are panning (Ctrl), and I couldn't run the library to check. I assumed it applies to any two held keys. If it only applies to rotation, the answers would be `altFraction` 1.00 and `ctrlSameDistance` false (Ctrl would move about 1.41 times as far). I also assumed Alt+Right on its own turns `alpha` as usual, since the notes only mention Alt changing the Up key.
