I wrote `/home/dev/13cc11/app/src/turntable.ts`. `spinAround` turns the camera with the library's `interpolateArcRotateCamera` at its default easing, in equal steps of at most a quarter turn. The goal it passes holds only `alpha`, so distance, height angle and target stay put. Before starting it clears any leftover drag or wheel momentum. At the end it makes `alpha` exactly start + 2π·turns. I couldn't type-check or run it, since the library isn't here.

Things I wasn't sure of:
- **Which way the transition goes round:** the notes don't say whether `interpolateArcRotateCamera` takes the shortest way round for `alpha`. If it does, one call would leave the camera still for 1 or 2 turns and turn it backwards for 0.75. That's why I used quarter-turn steps: they go forward either way.
- **Possible slowdowns:** the cost is that if the library's easing slows to a stop at the end of each step, the tour will ease a little every quarter turn instead of in one long glide. If you know it doesn't take the shortest way, a single call with the final `alpha` would be smoother. But with that easing it could make a big leap on the first frame of a 2-turn tour.
- **Alpha limits:** if the camera has `lowerAlphaLimit`/`upperAlphaLimit` set that rule out the full turn, the function rejects without moving the camera. The library would clamp the goal anyway, so the camera would stop part way otherwise.
