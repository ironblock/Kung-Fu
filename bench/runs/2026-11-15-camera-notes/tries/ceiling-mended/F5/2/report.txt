**What I wasn't sure of:**

I chose false because the controls don't handle pointer lock in any other way, so a drag probably uses the frozen `clientX`/`clientY` and sees no motion. If it reads `movementX` instead, a held-button drag would turn.
- **`touchDrag`:** This is also inferred. The free-camera notes don't mention touch; the touch note (19) is about the arc-rotate controls. I chose true because a touch press counts as button 0 and the library uses pointer events elsewhere. It would be false if the free controls only listen for mouse events, or if the browser takes the finger drag as a scroll because the canvas lacks `touch-action: none`.
