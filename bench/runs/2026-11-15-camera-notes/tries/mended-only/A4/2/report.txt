I wrote `/home/dev/80a8d4/app/notes/over-the-top.json` with the values below. I worked them out from the standard spherical-position formula (`x = r·cos(alpha)·sin(beta)`, `y = r·cos(beta)`, `z = r·sin(alpha)·sin(beta)`) and did not run Babylon Lite, since it isn't installed here.

- **eyeX / eyeY:** about -4.794 and 8.776. A negative beta puts the eye on the same side as beta = +0.5 with alpha rotated by PI, so the eye is still above the target.
- **upright:** true. The up vector stays world +Y and the view direction is not parallel to it, so the picture is not flipped.
- **sameAsOtherSide:** true. The eye matches the fresh `(PI, 0.5, 10)` camera, but its z is about 6e-16 off because `Math.sin(Math.PI)` is not exactly zero. That is floating-point noise, not a visible difference.

Things I'm not sure of:
- **Position without a frame:** I assumed `position` is recomputed from alpha/beta/radius when read. If Lite only updates it during a render or view-matrix pass, the stored eye could still be the pre-write (4.794, 8.776, 0). Check this in the library if it matters.
- **Beta not clamped:** Your notes (item 18) say a direct beta write is not clamped with no limits set, which I relied on for beta staying at -0.5.
- **Library behaviour:** I could not confirm any of this against the 1.39.0 source, so treat the values as derived from the Babylon convention rather than observed.
