# MEND

Each checker case was reproduced by a test before rewriting; the checker was right on all ten. Each probe gained a case for the exception.

- n01: was "attachControl only adds drag and wheel input to the inertialAlphaOffset/inertialBetaOffset/inertialRadiusOffset fields; a callback on scene._beforeRender applies them each frame. Called without a scene, the camera never moves." -> now "attachControl's drag and wheel only add to the inertialAlpha/Beta/RadiusOffset fields, applied by a callback on scene._beforeRender; with no scene they never move the camera. A two-finger pinch writes radius at once, scene or not."
- n02: was "Assigning a new object to ArcRotateCamera.target does not mark the camera dirty, and later writes to that plain object never do. The new target shows up only at the next alpha/beta/radius write. Write target.x/y/z in place." -> now "Assigning a new object to ArcRotateCamera.target does not mark the camera dirty, nor do writes to it. It shows up at the next alpha/beta/radius write that changes the value (cam.radius = cam.radius does not). Write target.x/y/z in place."
- n05: was "The lower/upper alpha, beta and radius limit fields do nothing until setCameraLimits runs. From then on each alpha/beta/radius write is clamped in the same statement; the call itself clamps the pose and zeroes that inertial offset." -> now "Hand-set lower/upper alpha/beta/radius limit fields clamp no write until setCameraLimits runs (interpolateArcRotateCamera clamps its goals anyway). After it each write is clamped at once; the call clamps the pose and zeroes that offset."
- n14: was "GeospatialCamera clamps pitch against the radius it is applied with: from 4*planetRadius (the start) pitch is forced to 0.001, falling linearly from 2R. Set radius before pitch, or both in one setGeospatialOrientation call." -> now "GeospatialCamera clamps pitch against the radius it is applied with: from 4*planetRadius pitch is forced to 0.001, falling linearly from 2R; the start radius is 4R (or 10 if larger). Set radius first, or both in setGeospatialOrientation."
- n10: was "Arc-rotate keys work only if enableArcRotateKeyboardControls() ran before attachControl and keyboard is true or an object. Arrows add 1/100 rad per frame, Ctrl+arrows pan, Alt+Up/Down zoom by 1/25; the canvas gets tabIndex 0." -> now "Arc-rotate keys need enableArcRotateKeyboardControls() before attachControl and keyboard true or an object. A held arrow adds 1/100 to the inertial offset each frame (1/100/sqrt2 per axis for two), so turns speed up; Ctrl+arrows pan."
- n15: was "GeospatialCamera.center returns its live inner object: writing center.x/y/z in place changes nothing else and moves no eye. Assign a whole new object to center (or use setGeospatialOrientation) to re-orbit." -> now "Writing GeospatialCamera.center.x/y/z in place moves no eye at once, but the next yaw/pitch/radius write orbits the changed center. Assign a whole new object to center (or use setGeospatialOrientation) to re-orbit at once."
- n16: was "createGeospatialCamera starts at center (R,0,0), yaw 0, pitch 0.001, radius 4R, nearPlane 1, farPlane 16R. Limits: radiusMin 10 (absolute), radiusMax 4R, pitchMax PI/2-0.01; radius writes are clamped to these." -> now "createGeospatialCamera starts at center (R,0,0), yaw 0, pitch 0.001, radius 4R, nearPlane 1, farPlane 16R; limits radiusMin 10, radiusMax 4R, pitchMax PI/2-0.01 clamp radius writes. If 4R < 10 it starts at 10 and writes above 10 give 4R."
- n06: was "After setCameraLimits, a limit field changed by hand applies at the next alpha/beta/radius write, not at once. The function setCameraLimits returns stops clamping but leaves the limit fields set." -> now "After setCameraLimits, a limit field changed by hand applies at the next alpha/beta/radius write that changes the value (cam.alpha = cam.alpha does not), not at once. The function setCameraLimits returns stops clamping, fields kept."
- n18: was "A change to GeospatialCamera.limits applies at the next yaw/pitch/radius/center write. limits.pitchDisabledRadiusScale = null allows full pitch at any radius." -> now "A change to GeospatialCamera.limits applies at the next yaw/pitch/radius write that changes the value, or at any center assignment (cam.center = cam.center works). limits.pitchDisabledRadiusScale = null allows full pitch at any radius."
- n33: was "attachFreeControl stops look inertia once it falls below speed * 0.001, so at a high speed (1000) a drag turns once with no glide." -> now "attachFreeControl stops look inertia once the decayed turn (drag px / angularSensitivity, times inertia each frame) falls below speed * 0.001, so at speed 1000 a 200 px drag turns once with no glide while a 3000 px drag still glides."

Dropped: none.

n10 no longer lists Alt+Up/Down zoom by 1/25 or tabIndex 0, to make room for the exception; its probe still tests both.
