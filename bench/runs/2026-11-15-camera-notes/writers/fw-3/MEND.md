# Mended notes

Each checker case was confirmed by a test before the note was changed; every probe of a changed note was extended with a `mended:` case that shows the new wording, and all 50 probes pass. No note was dropped; the checker was right on all 16.

Beyond the checker's cases: alpha/beta/radius setters (arc-rotate and geospatial) skip a write of the same value, so n03, n13 and n39 now say "a write that changes". The `fails_if` field of each changed note was updated to match its new wording.

- n02 (wider). Was: "Writing lowerRadiusLimit, upperBetaLimit etc. straight onto a camera clamps nothing until setCameraLimits has been called on it once; radius = 50 with upperRadiusLimit 12 stays 50, also under attachControl." Now: "Limit fields (upperRadiusLimit etc.) written straight onto a camera clamp no write until setCameraLimits has been called on it: radius = 50 with upperRadiusLimit 12 stays 50. interpolateArcRotateCamera clamps its goals to them anyway."
- n03 (wider). Was: "setCameraLimits clamps the current pose at once, and from then on every alpha/beta/radius write is clamped in the same statement and zeroes that inertial offset; limit fields written later are honoured on the next write." Now: "setCameraLimits clamps the current pose at once; from then on each write that changes alpha/beta/radius is clamped in the same statement, using the limit fields as they are then, and zeroes that inertial offset only if it hit a bound."
- n13 (wider). Was: "An ArcRotate camera's target is an observable vector: write target.x/y/z in place. Assigning a new object to camera.target leaves worldMatrix stale, and later writes to that plain object are not seen either." Now: "An ArcRotate camera's target is an observable vector: write target.x/y/z in place. Assigning a new object to camera.target leaves worldMatrix stale until a write changes alpha, beta or radius; that uses the object as it is then."
- n09 (wider). Was: "attachControl's keyboard option does nothing unless enableArcRotateKeyboardControls() ran before attachControl. Keys are heard on the canvas (tabIndex set to 0) and held keys add 1/angularSensitivity (default 100) once per frame." Now: "attachControl's keyboard: true is ignored unless enableArcRotateKeyboardControls() ran first. Keys are heard on the canvas (tabIndex made 0 if no tabindex attribute); held arrows add 1/angularSensitivity (default 100) per frame, normalised."
- n29 (wider). Was: "resolveCameraViewport measures camera.viewport.y from the bottom but returns y from the top: {x:0,y:0,width:0.5,height:0.5} on 800x600 gives {x:0,y:300,width:400,height:300}; fractions are clamped to [0,1]." Now: "resolveCameraViewport counts camera.viewport.y from the bottom but returns y from the top: {x:0,y:0,width:0.5,height:0.5} on 800x600 gives {x:0,y:300,width:400,height:300}. Edges are clamped to the canvas: {x:-0.5,width:1} gives width 400."
- n39 (wider). Was: "Changing camera.limits on a geospatial camera re-clamps nothing until the next yaw/pitch/radius/center write." Now: "Changing camera.limits on a geospatial camera re-clamps nothing until the next center write or the next yaw/pitch/radius write that changes the value; cam.radius = cam.radius is skipped and applies nothing."
- n18 (wider). Was: "attachFreeControl moves on KeyW/A/S/D and the arrows, up on Space/PageUp, down on ShiftLeft/ShiftRight/PageDown, matched by event.code on keys heard by the canvas (tabIndex set to 0)." Now: "attachFreeControl moves on KeyW/A/S/D and the arrows, up on Space/PageUp, down on ShiftLeft/ShiftRight/PageDown, matched by event.code on keys heard by the canvas (tabIndex set to 0 if it has no tabindex attribute)."
- n20 (wider). Was: "attachFreeControl turns on a drag with button 0, 1 or 2 (yaw += dx/angularSensitivity, right drag turns right, down drag looks down); pitch is clamped to +-(PI/2 - 0.01)." Now: "attachFreeControl turns on a drag with button 0, 1 or 2 (right drag turns right, down looks down); a drag adds dx/angularSensitivity to a turn velocity applied each frame, then times inertia, so it coasts. Pitch is clamped to +-(PI/2-0.01)."
- n22 (wider). Was: "Each frame a held key adds speed*deltaMs/sqrt(100000) to a velocity that is applied, then multiplied by inertia, so a free camera keeps coasting after the key is released." Now: "Each frame a held key adds speed*max(deltaMs,1)/sqrt(100000) to a velocity that is applied, then multiplied by inertia, so a free camera keeps coasting after the key is released."
- n15 (wider). Was: "interpolateArcRotateCamera ends with alpha set exactly to the goal, unwrapped: a goal of 2*PI from alpha 0 finishes on the first frame with alpha 2*PI. A radius goal beyond the camera's limits settles on the limit." Now: "interpolateArcRotateCamera ends with alpha, beta and radius set exactly to the goal clamped to the limit fields, alpha unwrapped: a goal of 2*PI from alpha 0 ends on the first frame at 2*PI; a goal past a limit ends on the limit."
- n16 (wider). Was: "Each frame interpolateArcRotateCamera moves 1 - 2^(-dt/interpolationFactor) of the remaining way, dt being the frame delta in seconds and the factor 0.1 by default; a factor <= 0 snaps on the first frame." Now: "Each frame interpolateArcRotateCamera moves 1 - 2^(-dt/interpolationFactor) of the remaining way, dt being the frame delta in seconds (a delta <= 0 counts as 1/60 s) and the factor 0.1 by default; a factor <= 0 snaps on the first frame."
- n10 (wider). Was: "Arc-rotate keys: ArrowUp lowers beta and ArrowRight raises alpha; with Ctrl the arrows pan (inertialPanningX/Y); with Alt, ArrowUp lowers radius by 1/zoomingSensitivity (default 25) per frame." Now: "Arc-rotate keys: ArrowUp lowers beta, ArrowRight raises alpha; Ctrl+arrows pan (inertialPanningX/Y); with Alt, a held ArrowUp adds 1/zoomingSensitivity (default 25) to inertialRadiusOffset each frame, so radius falls faster each frame."
- n04 (wider). Was: "The function setCameraLimits returns stops all clamping but leaves the limit fields set on the camera." Now: "The function setCameraLimits returns stops all clamping but leaves the limit fields set on the camera. Only the disposer from the latest setCameraLimits call works; an earlier one does nothing."
- n48 (wider). Was: "attachControl's inertia ignores the frame delta: each frame adds the whole offset, then multiplies it by inertia, at any frame rate." Now: "attachControl's inertia ignores the frame delta: each frame adds the whole rotation or zoom offset, then multiplies it by inertia; a pan offset is added times radius/1000, then multiplied by panningInertia."
- n41 (wider). Was: "flyGeospatialCameraToAsync times the flight from the frame deltas given to _beforeRender (durationMs default 1000) and turns yaw the short way round (3 to -3 passes through PI)." Now: "flyGeospatialCameraToAsync times the flight from the frame deltas given to _beforeRender (durationMs default 1000; a delta <= 0 counts as 1000/60 ms) and turns yaw the short way round (3 to -3 passes through PI)."
- n38 (false). Was: "A geospatial center within about 0.04 degrees of a pole (+-Z) is moved to that latitude, keeping its distance from the origin." Now: "A geospatial center written with spherical latitude asin(z/|center|) beyond +-87.13 degrees (0.05 rad from the +-Z pole) is moved to +-87.13, keeping its distance from the origin and its longitude."
