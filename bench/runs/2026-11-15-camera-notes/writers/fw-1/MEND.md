# Mended notes

Each change: id, what it said, what it says now. All 13 checker cases were confirmed by a test before mending; none dropped.

- n01: was "attachControl without a scene never moves the camera: drags and wheel only add to inertialAlphaOffset, inertialRadiusOffset and the like, which are applied only by the per-frame hook it pushes on scene._beforeRender." -> now "attachControl without a scene moves nothing on drags or wheel: they only add to inertialAlphaOffset, inertialRadiusOffset and the like, applied by the hook it pushes on scene._beforeRender. A two-finger pinch still writes radius at once."
- n02: was "Writing lowerRadiusLimit (or any limit field) on the camera does nothing until setCameraLimits has run; after that, every write to alpha, beta or radius is clamped in the same statement, using the camera's current limit fields." -> now "Hand-written limit fields clamp no alpha/beta/radius write until setCameraLimits has run; after it, a write that changes the value is clamped at once to the current fields. interpolateArcRotateCamera obeys the fields either way."
- n18: was "Assigning a new object to an ArcRotateCamera's target is not seen until alpha, beta or radius next changes, and later edits to that object are never tracked; move the target by writing target.x/y/z in place." -> now "Assigning a new object to an ArcRotateCamera's target marks nothing dirty: it and later edits to it show only when the matrix is next rebuilt (at the first read, or after an alpha, beta or radius change). Edit target.x/y/z in place."
- n33: was "GeospatialCamera clamps pitch to getEffectivePitchMax of the current radius: pitchMin (0.001) at the default radius 4*planetRadius. Set radius first or use setGeospatialOrientation; zooming out lowers pitch for good." -> now "GeospatialCamera clamps pitch to getEffectivePitchMax of the asked radius, before radius is clamped: pitchMin (0.001) at the default 4*planetRadius. Set radius first or use setGeospatialOrientation; zooming out lowers pitch for good."
- n14: was "interpolateArcRotateCamera rejects its promise if alpha, beta, radius or target change between frames by anything else, including a second interpolateArcRotateCamera on the same camera; its first frame zeroes all inertial offsets." -> now "interpolateArcRotateCamera rejects its promise if alpha, beta, radius or target change by anything else between its frames, a second call on the camera included; a change before its first frame becomes the start. That frame zeroes inertia."
- n11: was "Each frame attachControl adds the whole inertial offset to alpha (and the like) and then multiplies the offset by inertia, so with inertia 0 a drag is applied exactly once and stops." -> now "Each frame attachControl adds the whole alpha/beta offset (subtracts inertialRadiusOffset from radius), then multiplies it by inertia; pan offsets decay by panningInertia instead, so inertia 0 stops a drag or zoom at once but not a pan."
- n35: was "Editing camera.center.x/y/z in place moves nothing on a GeospatialCamera; only assigning a Vec3 to center re-orbits, and the assigned object is copied, not kept." -> now "Editing camera.center.x/y/z in place on a GeospatialCamera moves nothing until the next yaw, pitch or radius change, which re-orbits around the edited centre; assigning a Vec3 to center re-orbits at once and copies it."
- n27: was "Assigning camera.ortho = null by hand leaves getProjectionMatrix returning the cached orthographic matrix until something else rebuilds it (a fov write did); disableOrthographicCamera switches at once." -> now "Assigning camera.ortho = null by hand keeps the cached orthographic matrix, and the rebuild after a fov write still has the ortho p[12], p[13] and p[15]=1; disableOrthographicCamera clears those and switches at once."
- n13: was "Each frame a held arrow adds 1/angularSensitivity (default 100) to the offsets: ArrowRight raises alpha, ArrowUp lowers beta; Ctrl+ArrowRight pans; Alt+ArrowUp cuts radius by 1/zoomingSensitivity (25)." -> now "Each frame held arrows add 1/angularSensitivity (100) to the offsets, split over two held keys (0.01/sqrt2 each): ArrowRight raises alpha, ArrowUp lowers beta; Ctrl+Arrow pans; Alt+ArrowUp cuts radius by 1/zoomingSensitivity (25)."
- n16: was "When the setCameraLimits clamp hits a bound it zeroes that channel's inertial offset; the function setCameraLimits returns stops the clamping but leaves the limit fields set." -> now "When the setCameraLimits clamp hits a bound it zeroes that channel's inertial offset. Only the function returned by the latest setCameraLimits call stops the clamping; it leaves the limit fields set."
- n43: was "A wheel event heard by attachGeospatialControls during a flyGeospatialCameraToAsync ends the fly on the next frame and resolves its promise." -> now "A wheel event with nonzero deltaY heard by attachGeospatialControls during a flyGeospatialCameraToAsync ends the fly on the next frame and resolves its promise; one with deltaY 0 (a sideways scroll) does not."
- n21: was "attachFreeControl clamps _pitch to +-(PI/2 - 0.01), and dragging the mouse down lowers _pitch by pixels / angularSensitivity." -> now "attachFreeControl clamps _pitch to +-(PI/2 - 0.01). A downward drag lowers _pitch by pixels / angularSensitivity on the next frame, then coasts by inertia: about 10 times that in all at the default 0.9, exactly that at 0."
- n22: was "Each frame a held move key adds speed * deltaMs / sqrt(100000) to the free camera's move, which then decays by inertia, so the distance per frame scales with deltaMs." -> now "Each frame a held move key adds speed * max(deltaMs, 1) / sqrt(100000) to the free camera's move, which then decays by inertia, so the distance per frame scales with deltaMs and a 0 ms frame moves as 1 ms does."

Dropped: none.
