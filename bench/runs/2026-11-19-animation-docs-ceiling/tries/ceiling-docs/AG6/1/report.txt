I read both files and answered from the doc's `goToFrame` description. It sets `currentTime = frame / frameRate` (30/60 = 0.5 s) and then pauses. It evaluates the pose immediately only for manual property clips, or for engine-backed clips when you pass an engine. glTF clips from `createAnimationGroups` therefore stay unposed after a plain `goToFrame(group, 30)`, whether they were never played, stopped, or playing. The pose only appears on the next tick. Passing the engine is the one case that poses right away.

I couldn't run anything, so these answers rest on the doc alone; the `.d.ts` gives signatures only. I'm least sure about `withEnginePosed` on a never-played clip, since the doc doesn't say whether the stopped state blocks the one-shot evaluation. I assumed it doesn't. The `playThenSeekPosed` answer assumes the same no-engine rule applies to a clip that has just been played.
