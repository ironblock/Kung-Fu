I answered from the doc and the type declarations, since I couldn't run anything. With no blending, the groups run in manager order and the last write wins, so B wins at start (30) and a brand-new group for A is appended last (10).

I'm unsure about the two re-add answers. `AnimationGroup` carries `_animationOrder` and `_animationOrderManager`, and the doc says a reattached older group keeps its first-attachment position instead of being appended. I read that as applying to `addAnimationGroup` itself, which gives 30 and index 0 for both re-add cases. But the doc describes it under the compat facade, so it might not hold for native `addAnimationGroup`. If re-adding just appends, `xAfterReAddingA` would be 10 with index 1, and `xAfterClearThenBThenA` would be 10. Please check those against a real run before building on them.
