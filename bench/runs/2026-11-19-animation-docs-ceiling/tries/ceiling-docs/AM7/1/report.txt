I worked these out from the doc, since nothing could be run. The skeletal mixer uses plain weighted sums for translation, with no normalising and no blending toward rest. Two full-weight clips on `Upper` therefore give 2 + 6 = 8, and that holds whichever clip is added first, because only additive layers depend on order. With the masks, `Lower` is animated only by A, so it stays at 3 whatever B's weight is.

I'm fairly sure of the first two values. The `Lower` values assume that a masked-out target contributes nothing to the sum. The doc says masked targets "stay at bind pose" and says Babylon.js pauses them, but it never states this for the weighted mixer. If the mixer instead counted B's half weight against `Lower`'s rest pose, the last value would differ.
