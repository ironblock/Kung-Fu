I wrote `notes/frame-step.json` with all four values set to `null`, because neither file shows what `runFrameInterpolation` does with a frame's delta. The declarations only give `step: (deltaSeconds: number) => boolean`, and the doc never mentions frame interpolation. If the delta is simply divided by 1000, the values would be 0, -5, 1 and 40 after your ×1000 scaling. But the implementation could clamp negative deltas to 0, enforce a minimum step, or cap long frames, and that is exactly what decides your pause question. I didn't want to put a guess in a file that looks like a verified answer. Once you can read the `frame-interpolation` source, or log what the step receives in your app, the four numbers are quick to fill in.
