I did not write `notes/inset-slide.json`, because I can't get real values for it. The declarations in `camera-api.d.ts` give only signatures. `resolveCameraViewport` returns a `PixelViewport` (`x`, `y`, `width`, `height`), and `getEffectiveAspectRatio` returns a number. Neither file says whether the viewport is clamped to the canvas or how the aspect is derived, and that is exactly what decides whether the frame and inset line up. Working it out by hand would just be a guess. I made no changes in the app.

To get the real numbers, run this once in the app, where the library is installed:

```js
import { createArcRotateCamera, resolveCameraViewport, getEffectiveAspectRatio } from "@babylonjs/lite";
import { writeFileSync } from "node:fs";

const cam = createArcRotateCamera(0, 0, 5, { x: 0, y: 0, z: 0 });
cam.viewport = { x: 0.8, y: 0.1, width: 0.3, height: 0.3 };

const v = resolveCameraViewport(cam, 1000, 500);
const aspect = getEffectiveAspectRatio(cam, 1000, 500);
writeFileSync("notes/inset-slide.json", JSON.stringify({
  x: v.x, y: v.y, width: v.width, height: v.height,
  aspect: Math.round(aspect * 100) / 100,
}, null, 2) + "\n");
```
