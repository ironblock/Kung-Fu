I wrote `app/src/fly-to-place.ts`. It calls the library's `flyGeospatialCameraToAsync` and resolves `true` only if the camera's final yaw, pitch, radius and center match the place within a small tolerance. It is untested: I could not compile or run it because the library isn't on this machine.

Things I'm not sure of:

- **Arrival is inferred, not reported.** The declared `flyGeospatialCameraToAsync` returns `Promise<void>`, so the library doesn't say whether a flight finished or was cancelled. I compare the camera's state with the place when the promise settles. A cancelled flight that happens to end on the same spot would count as arrived.
- **Cancelled flights might never settle.** If the library leaves a cancelled flight's promise pending, `flyToPlace` will hang too. I can't check this from the declarations.
- **The import may not be exported from the package root.** `flyGeospatialCameraToAsync` is declared in an internal file, so `@babylonjs/lite` may not re-export it.
- **Tolerances are guesses.** Lengths use 1e-5 of `camera.limits.planetRadius`, and angles use 1e-5 radians.
- **`tsconfig.json` points at a missing source tree.** Its `paths` entry for `@babylonjs/lite` refers to `../babylon-lite/...`, which doesn't exist here.
