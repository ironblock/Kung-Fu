I wrote `src/limited-orbit.ts`, which turns on the library's standard controls with `attachControl` and keeps the zoom distance in range with the library's `setCameraLimits`. The declarations say `setCameraLimits` brings an out-of-range camera inside right away and then re-clamps on every distance change, so neither hard scrolling nor pinching can get past either limit, even for one frame. The returned function removes the canvas listeners and the per-frame hook, removes the limit, and restores whatever zoom limits the camera had before; calling it twice is safe.

Things I'm not sure of:
- **Untested:** none of this has been compiled or run, since the library isn't here. It relies on the docs being accurate, and it assumes `attachControl` and `setCameraLimits` can be imported from `"@babylonjs/lite"`. The declarations didn't show what the package actually exports.
- **Other limits on the same camera:** the library's cleanup removes the camera's whole clamp, not just our part. If other code also sets limits on this camera (for example, how far it can tilt), those would stop working after our cleanup runs. I only found my own file under `src/`, but I couldn't list the folder, so I may have missed something.
- **Choices I made:** the function throws an error if `minDistance` is negative or larger than `maxDistance`. I also had cleanup remove the zoom limit along with the controls, rather than leaving it on the camera.
