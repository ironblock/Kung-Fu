I wrote `/home/dev/4c426b/app/src/big-world-fly.ts`. It attaches the library's default `attachFreeControl` to your canvas, plus 19 more copies on hidden canvases that only receive the key and blur events your canvas gets. So each movement key, including rise and sink, runs the library's own movement 20 times, while mouse look comes only from the one real copy. The returned function removes my listeners and detaches all 20 copies. None of this has been compiled or run, since the library isn't here.

What I wasn't sure of:
- **Why I didn't just set `camera.speed` 20 times higher:** in Babylon.js, speed also sets the point where leftover mouse-look coasting is cut off. A higher speed would make every drag turn the camera less. I couldn't check whether Lite does the same. If it doesn't, `camera.speed *= 20` is the simpler fix.
- **What the copies rely on:** each `attachFreeControl` call must keep its own movement state and add to the camera's position rather than overwrite it. It must also read keys from the canvas or window and accept the copied key events my code sends. If not, you'll most likely just see normal speed. But if the idle copies overwrite the camera's rotation, mouse look would break, so check that first.
- **Import:** I assumed `attachFreeControl` can be imported straight from `"@babylonjs/lite"`.
