I did not write `notes/arrow-keys.json`, and I can't give you the three values from these files. The declarations don't cover what you asked, and I can't run the library here.

What the declarations do say:
- Default sensitivities are `angularSensitivity` 100, `panningSensitivity` 50 and `zoomingSensitivity` 25. Those are the divisors on the keyboard path, so they don't tell us the per-frame step.
- Arrow keys are documented as "rotate or pan" for left/right and "rotate up, pan up, or zoom in" for up. That suggests Up drives beta, not alpha, so Right+Up should leave alpha alone. That is my reading of the comments, not a measurement, and the comments don't rule out coupling through inertia or limits.
- Nothing in the arc-rotate keyboard types mentions Alt or Ctrl. The only Ctrl+arrow behaviour documented is tilt on the geospatial camera, which isn't the camera you're using. So questions 2 and 3 can't be answered from these files.

Writing invented numbers into the JSON would be worse than leaving it unwritten, so I left it alone. The app directory wasn't listed, since the tools here can't list directories, and I made no changes there.

To get real values, someone needs to run the 60-frame test with the actual library, Alt and Ctrl included. If you can get the library's keyboard source, or a run log from a machine that has it, I can work out the three values from that.
