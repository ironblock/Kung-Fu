I implemented the fly controls from scratch rather than wrapping `attachFreeControl`, because multiplying `camera.speed` by 20 would also raise the look-inertia cutoff threshold (note 65: `speed * 0.001`), shortening the mouse-look coast and changing the total rotation per drag. My version applies the 20× factor only to keyboard acceleration while using the original speed for the look-inertia threshold, so mouse look is bit-identical to the library default.

The one thing I was not sure of: the exact sign convention for vertical mouse drag (I used `pitchVel -= dy / angSens` so that dragging down looks down, matching note 40's "down looks down"). If the library's internal convention is the opposite, the vertical mouse-look direction would be inverted—but the magnitude and coasting behavior would still match.
