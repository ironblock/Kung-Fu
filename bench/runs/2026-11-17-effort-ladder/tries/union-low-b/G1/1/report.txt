I wrote `src/mode-limits.ts` which assigns the mode's `GeospatialLimits` to `camera.limits` (so the camera's own internal clamping tracks the right bounds) and then redefines the `radius` and `yaw` accessors on the camera to clamp every write to the mode's range, using symbol-keyed backing stores so repeated calls (mode switches) correctly re-capture the current value and apply the new mode's bounds. One thing I was not fully sure of: the notes confirm the camera clamps `radius` (and `pitch`) internally via `limits`, but never explicitly state that it clamps `yaw` against `yawMin`/`yawMax` — so I added the explicit yaw wrapper to guarantee the requirement regardless.
