I wrote `src/mode-limits.ts` which sets `camera.limits` to the given mode's limits object and redefines `camera.radius` and `camera.yaw` as clamped own properties so that any subsequent write is kept within that mode's `radiusMin`/`radiusMax` and `yawMin`/`yawMax` ranges. The only thing I was not fully sure of is whether the library's internal frame loop might write to a private backing field (bypassing the public `radius`/`yaw` accessors) in a way that would evade the clamp — based on the type declarations and notes, all documented writes go through the public properties, so I expect this to hold, but I can't verify it without the implementation.
