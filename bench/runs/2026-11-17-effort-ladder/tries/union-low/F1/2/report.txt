I implemented the controls from scratch rather than wrapping `attachFreeControl`, because multiplying `camera.speed` by 20 would also raise the look-inertia stop threshold (`speed × 0.001`), causing the mouse look to coast less than the library default. By replicating the library's per-frame formulas directly—using the original `camera.speed` for the look threshold and `camera.speed × 20` for keyboard step—I get exact mouse look and 20× keyboard speed simultaneously.

I was not sure of the exact return type of `scene._beforeRender.add(…)` (I assumed it returns a zero-argument dispose function, consistent with the "the function returned by attachFreeControl removes its listeners" pattern); if it returns an object with a `.dispose()` method instead, that one line would need adjusting.
