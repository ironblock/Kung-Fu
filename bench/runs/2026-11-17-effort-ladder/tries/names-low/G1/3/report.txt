I created `src/mode-limits.ts` which replaces the camera's `radius` and `yaw` data properties with clamping accessor properties (via `Object.defineProperty`) and sets `camera.limits` to the supplied mode's limits object; each subsequent call re-aims the closures at the new limits and re-clamps the current values into the new range. I'm not sure whether the library's internal `setGeospatialOrientation` or control code might write to `radius`/`yaw` through a code path that bypasses the own-property trap (e.g., via a prototype setter or a stored reference), but based on the type declarations showing them as plain instance properties, the accessor approach should intercept all writes.
