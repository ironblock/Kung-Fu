I created `src/mode-limits.ts` which uses `Object.defineProperty` to replace the camera's `radius` and `yaw` properties with getter/setter pairs that clamp writes to the current mode's limits, and updates `camera.limits` to point at the active mode's `GeospatialLimits` object. One thing I was not sure of: whether the library's internal fly-to or interpolation code might write radius/yaw through a private path that bypasses the public property setters — if so, those writes would not be clamped, but based on the type declarations the public `radius`/`yaw` properties are the documented write surface.
