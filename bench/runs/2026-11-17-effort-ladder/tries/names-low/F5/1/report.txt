I wrote the analysis to `notes/pointer-lock.json`. The key finding is that `attachFreeControl` relies on `clientX`/`clientY` deltas, so pointer lock (which freezes those values) yields zero movement regardless of button state — you'll need your own mouse-look handler that reads `movementX`/`movementY` for the locked shooter mode. The one thing I wasn't 100% certain of is whether Babylon Lite 1.39.0 introduced any pointer-lock-aware path in the free-camera controls that isn't visible from the type declarations alone; the API surface shown gives no hint of it, so I assumed standard behavior.
