I wrote the analysis to `notes/same-frame.json`. The two lines are **not** safe in place: `spot.x = 5` mutates the vector the interpolation still holds a reference to, so the camera's target ends up at x = 5 instead of x = 1. The `camera.radius = 7` line is safe because the goal doesn't specify a radius, so the interpolation never touches it. I was not 100 % certain Babylon Lite copies vs. holds a reference for the target (the type declarations don't reveal the implementation), but the API design — passing `Vec3` by reference and the precedent from full Babylon.js — strongly points to the reference-holding pattern, which is what the answer assumes.
