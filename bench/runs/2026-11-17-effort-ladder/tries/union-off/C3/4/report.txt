I wrote `notes/arrow-keys.json` with the three answers derived from the "normalised" behavior described in note 9: holding two orthogonal arrow keys splits the input equally (each axis gets 1/√2 of the single-key rate), giving a 0.71 fraction for pure rotation; with Alt, Up becomes a zoom key so only Right drives alpha, yielding a 1.00 fraction; and with Ctrl, both keys pan but the normalized resultant keeps the target's travel distance the same. I was slightly uncertain whether the normalization applies before or after modifier interpretation (i.e., whether Alt+Up still counts as an "angular" key for normalization purposes), but note 39's explicit description of Alt+Up changing to a zoom action supports treating it as non-angular, hence no normalization partner for Right.
