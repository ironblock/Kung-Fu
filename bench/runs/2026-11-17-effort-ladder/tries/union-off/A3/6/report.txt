I wrote `src/screen-shift.ts` exporting `trackScreenShift`, which snapshots the camera's view matrices (copied, since Babylon returns in-place caches) at creation and on each `mark()`, then in `shift()` projects the given point under both the stored and current views and returns the CSS-pixel delta.

Things I was not fully sure of: (1) I assumed `Mat4` is a 16-element float array (standard Babylon) and copied it by index — if your build represents it differently the copy loop would need adjusting; (2) I assumed the canvas size is stable between `mark()` and `shift()` (dimensions are read once at construction), so a resize in between would skew the result; (3) I relied on `getEffectiveAspectRatio`, `getViewMatrix`, `getViewProjectionMatrix`, `getCameraPosition` and `projectWorldToScreen` all being re-exported from the `@babylonjs/lite` package root, matching how you import `Camera` — if any aren't at the root, the import specifier would need to point at the sub-module.
