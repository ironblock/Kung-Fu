I wrote `app/src/label-position.ts`, which projects the point with the library's view and projection matrices and sets `visible` only when the point has positive clip w and lies inside the canvas, ignoring the far plane. I could not compile or run it because the library isn't on this machine.

Things I'm not sure of:
- **Root exports:** I import `getViewMatrix`, `getViewProjectionMatrix`, `getEffectiveAspectRatio` and `projectWorldToScreen` from `"@babylonjs/lite"`, but the declarations only show them in `camera.d.ts` and `world-to-screen.d.ts`. If they aren't re-exported from the package root, the import will fail.
- **Floating origin:** I don't pass `worldOrigin`. If the camera uses floating origin, positions may be off, and I couldn't tell from the declarations how to supply the origin.
- **Behind-camera points:** `x` and `y` for these come from the perspective divide, so the arrow direction may be mirrored. The spec doesn't cover this case.
- **Orthographic cameras:** clip w is not a depth test there, so a point behind an ortho camera could be reported visible.
- **Canvas size:** I take CSS size from `clientWidth`/`clientHeight`, which ignores borders and rounds to whole pixels.
