I wrote `notes/inset-slide.json` with `{ "x": 800, "y": 50, "width": 300, "height": 150, "aspect": 2 }`, but those numbers are my hand calculation, not the library's output. The `.d.ts` file only has signatures, and I can't run Babylon Lite here, so I computed them from the viewport fractions and the 1000 × 500 backing size.

Things I'm not sure of:
- **Clamping:** `resolveCameraViewport` may clamp to the canvas. Unclamped, the inset spans x 800–1100, so the true width could be 200 rather than 300.
- **Y origin:** if the viewport's y is measured from the bottom, the CSS top would be 300 rather than 50.
- **Aspect:** 2.00 is what both the viewport shape (300 / 150) and the canvas (1000 / 500) give. If the function uses the camera's projection setup, it could differ.
