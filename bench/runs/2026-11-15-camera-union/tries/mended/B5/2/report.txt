I wrote `/home/dev/412f57/app/src/label-position.ts`. It projects the point with the library's own `getViewMatrix`, `getViewProjectionMatrix` and `projectWorldToScreen`, using the full canvas as the viewport. It takes `x`/`y` from `cssX`/`cssY`, and treats the point as visible when `clipW > 0`, `behindCamera` is false, and the CSS position is inside the canvas. It ignores the far plane and never runs the code, since the library isn't on this machine.

I'm not sure of these points:
- **Imports:** I assumed the three functions and the `Camera` type are exported from the `@babylonjs/lite` root. The `.d.ts` file doesn't show the package index, so this could fail at build time.
- **Orthographic cameras:** `clipW` is constant for them, so the "in front of the camera" test may not do what you want. The notes don't cover this.
- **Floating origin:** I didn't pass `worldOrigin`. If the camera uses floating origin, the result may be off.
- **Unlaid-out canvas:** When the canvas has zero size, the function returns `visible: false` at `(0, 0)` to avoid the library's `RangeError`.
