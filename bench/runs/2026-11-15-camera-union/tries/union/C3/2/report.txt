I wrote `notes/arrow-keys.json` with `{ "rotateFraction": 0.71, "altFraction": 0.71, "ctrlSameDistance": true }`. I could not run the library, so these values are my reading of the notes, not measured results. The answers assume the library normalises the held-arrow input vector to length 1 (notes 9 and 57). Under that model, a diagonal gives each axis 1/√2 ≈ 0.71 of its single-key rate, so alpha turns 0.71 as far and the pan distance stays the same. If the library instead scales each axis independently, the rotate fraction would be 1.00 and the Ctrl pan would be √2 times farther, so `ctrlSameDistance` would be false. The Alt value is the least certain. Note 39 says Alt routes Up to zoom, so if Up is dropped from the rotate vector under Alt, `altFraction` would be 1.00 instead of 0.71. Checking the library source or a real 60-frame run would settle all three.
