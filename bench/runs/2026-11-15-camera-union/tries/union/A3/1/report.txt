I wrote `src/screen-shift.ts` (at `/home/dev/a7493f/app/src/screen-shift.ts`). `mark()` and `trackScreenShift` copy the camera's view and view-projection matrices, and `shift()` projects the point through both the marked and the current matrices and returns the CSS-pixel difference. I did not compile or run it, since the library isn't on this machine.

Things I'm not sure of:
- **Imports:** I assumed `getViewMatrix`, `getViewProjectionMatrix`, `getEffectiveAspectRatio`, `getCameraPosition` and `projectWorldToScreen` are exported from the package root, as `Camera` is. If they aren't, the import paths need changing.
- **Stale target:** Per your notes (item 3), assigning a new object to `ArcRotateCamera.target` doesn't dirty the camera. Until the next alpha/beta/radius change, `shift()` will report no movement for that change. Writing `target.x/y/z` in place avoids this.
- **Resized canvas:** Each side is projected with the canvas size it was taken at, so a resize shows up as movement in CSS pixels.
- **Matrix type:** `Mat` is derived from `getViewMatrix`'s return type because I couldn't see `Mat4`'s definition, and the copy uses a cast.
