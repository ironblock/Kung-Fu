`history` now takes an optional `limit`. The log is kept newest-logged-first, so it takes the first `limit` of the part's movements, which keeps the existing order and ignores the day numbers. Each movement is still a copy. Without a limit, or with a limit at least as big as the list, the result is the same as before.

I made a limit that isn't a whole number of 1 or more throw a `RangeError`, as the other methods do for bad input. You didn't say what should happen in that case, so change it if you'd rather it be ignored.
