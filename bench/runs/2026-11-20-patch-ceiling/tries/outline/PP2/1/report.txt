I renamed the existing `fill` to a private `fillPlain` and put a new `fill` in front of it. The new `fill` swaps each `{name|fallback}` field for a placeholder, using the field's value if `fields` has one and the fallback text otherwise. It then runs the old code on the rest and puts the chosen text back afterwards. Because of that, values and fallbacks are never re-scanned for braces, and barred fields never reach `missing`.

I couldn't see the body of `fill`, so I assumed that `{{` is how a literal brace is written outside a field, and my scan skips over it. If the old code treats doubled braces differently, that skip is the part to check. I also treated a field as "has a value" when `fields` has its own string for that name, which may differ slightly from how the old code tests it.
