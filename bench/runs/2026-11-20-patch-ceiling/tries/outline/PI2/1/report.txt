I renamed the existing `nextStart` to a private `nextStartIgnoringLunch`, leaving its body untouched, and added a new exported `nextStart` in front of it. The new one calls the old one, and if the start it returns would overlap 750–790 it asks again from 790 or later. It passes through `NO_START`, so the usual "none left" answer is kept, and visits already in the log still block starts as before.

I couldn't see the original body, so I assumed a visit's length is `SLOTS[service] * SLOT_MIN` minutes and that `SLOTS` is a module-level constant. If `lengthOf` returns minutes, it would be cleaner to use that instead.
