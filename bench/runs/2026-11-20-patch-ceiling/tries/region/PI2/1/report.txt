I added `LUNCH_START` (750) and `LUNCH_END` (790) constants, and `nextStart` now skips any candidate start whose visit would overlap that window. A visit ending exactly at 750 or starting exactly at 790 is still allowed. Logged visits are checked as before, including any inside lunch. A skipped start just moves to the next slot, so the result is the first start where the whole visit fits, or `NO_START` if none is left.

I couldn't run anything or see the rest of the file, so this is untested. I assumed the two new constant names don't clash with anything else in the file.
