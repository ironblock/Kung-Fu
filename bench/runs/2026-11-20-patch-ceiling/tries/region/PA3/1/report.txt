`shift` now runs `release` and `assign` against a temporary log and pushes one entry onto the real log. The entry is the one `assign` produced, with `from` set to the berth `release` returned and `to` set to the target. A refusal still leaves the log untouched, and the return value and berth changes are as before.

I couldn't see `assign` or `release`, or the hidden `Move` fields, so two things are assumed:
- **Logging method:** I assumed those functions add entries with `log.push`. If they log some other way (for example, sorted insertion), the final `log.push` should be changed to match.
- **Extra fields:** I assumed any extra `Move` fields on `assign`'s entry are right for a combined move.
