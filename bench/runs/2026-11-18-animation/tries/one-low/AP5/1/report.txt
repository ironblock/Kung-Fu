I implemented the beacon as an animation task attached to the manager: it accumulates `deltaMs` into an elapsed counter, computes the position within the current period via modulo, and writes the appropriate linear rise/fall/zero value to `lamp.intensity` scaled by the current strength. The returned setter just reassigns the strength variable, so the rhythm (driven purely by the elapsed counter) is unaffected and the new peak appears on the next update.

I'm not sure of anything in particular — the task API is straightforward and the notes confirm that tasks are called during `updateAnimationManager` with the (possibly fixed) delta, and that multiple tasks coexist in one manager without interfering.
