I wrote `src/beacon.ts` which registers an `AnimationTask` on the given manager; each update advances a local elapsed-time counter, computes the phase within the period, and writes the triangular ramp (scaled by the current strength) to `lamp.intensity`. The returned closure simply stores the new strength for the next update, so it never touches the timing. I was not sure whether "more than 0" in the strength constraint means I should reject or clamp a zero value, so I clamped to [0, 1] — passing 0 effectively silences the beacon without error.
