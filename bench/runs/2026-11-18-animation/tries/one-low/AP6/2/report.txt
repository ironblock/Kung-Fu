I built the track as a single-track property-clip with linear interpolation and frame-based keyframes, then created a looping group whose time range spans from the first key to the last key so the built-in wrap-around carries the motion back to the start each cycle. The one thing I'm slightly unsure of is whether "goes straight back to the first key" means the last key's value should be visibly written for at least one frame before the jump; per the notes a looping group keeps `currentTime` in `[fromTime, toTime)`, so the exact last-key value is the asymptote it approaches but never lands on — in practice the difference is sub-frame and imperceptible.
