I created `src/skip-ahead.ts` which bypasses `updateAnimationManager` (and its fixed-step substitution) by directly invoking each task's `_update` with the requested `ms`, handling the category-handler batching path and `_preUpdate` in the same order the manager uses. I'm not fully certain whether `_preUpdate` is part of `updateAnimationManager`'s cycle or only the RAF loop, and I assumed the category handler is called once per update for all matching tasks (returning true to suppress individual updates) — if the real semantics differ, the blending path could misbehave.
