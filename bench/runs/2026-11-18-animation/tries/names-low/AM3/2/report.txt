I created `src/skip-ahead.ts` which advances every active task on the manager by `ms` milliseconds in a single pass (iterating in reverse so that self-removing tasks don't cause index drift). Since animation groups, weight fades, and any other custom logic are all registered as `AnimationTask` entries whose `_update` receives a `deltaMs`, this single loop advances clips, fades, and tasks alike as if that much time had elapsed, while leaving the manager's `fixedDeltaMs`, `running` flag, and frame-level callbacks (`_preUpdate`, `onUpdate`) untouched so the next normal frame steps exactly as before.

One thing I was not sure of: whether `_preUpdate` or `onUpdate` carry state-advancing logic that would also need to be invoked for a fully faithful "as if time passed" simulation. I chose to skip them on the assumption they are frame-level bookkeeping (render triggers, frame counters) rather than animation-state advancement; if either of them in your app actually mutates animation state, you'd want to fold them in.
