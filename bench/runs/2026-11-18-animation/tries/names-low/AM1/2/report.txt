I created `src/hand-over.ts` which registers a temporary `AnimationTask` on the manager that linearly ramps `to.weight` toward 1 and `from.weight` toward 0 over `durationMs`, removing itself when done; a module-level `WeakMap` tracks the active task per group so a re-invocation (including a reverse call mid-fade) cleanly supersedes the previous one by removing it and restarting from the current weights. The one thing I was not sure of is whether `removeAnimationTask` is a safe no-op when called on a task that has already been removed (e.g., if the manager was cleared externally); I assumed it is, which is the convention in Babylon-style APIs.
