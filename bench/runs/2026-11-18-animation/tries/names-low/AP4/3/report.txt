I wrote `src/release.ts` which iterates every group on the manager via `getAnimationGroups`, checks each group's `targetedAnimations` and its `_propertyMixer` tracks for a match on both the target object (identity) and the dotted path, and calls `stopAnimation` on any that match so they no longer write to that property. I'm not 100% sure whether `stopAnimation` alone is sufficient to remove a group's contribution from an in-flight blended mixer frame (as opposed to just preventing future frames), but since you update the manager yourself each frame, the next tick will only accumulate from the remaining active groups.
