I implemented `jumpToFrame` by delegating to the library's `goToFrame` function, which is the purpose-built API for setting an `AnimationGroup`'s current time to a given frame (in the clip's own frame rate) while preserving its playing state, speed ratio, and loop setting. I'm confident in this, though I note I couldn't verify the runtime behavior of `goToFrame` since the library isn't on this machine — I'm relying on its declared signature and the fact that it's the standard "scrub to frame" operation in the animation module.
