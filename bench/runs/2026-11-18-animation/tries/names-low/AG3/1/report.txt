I created `src/jump-to-frame.ts` which delegates to the library's `goToFrame` function — it sets the group's current time to the given frame (in the clip's own frame rate) while leaving `isPlaying`, `speedRatio`, and `loopAnimation` untouched, so the clip continues from the new point at its own speed and loop mode. I'm not sure whether `goToFrame` internally forces an immediate re-evaluation or defers to the next tick, but since the group is already playing (ticked by the scene or animation manager each frame), the jump will take effect on the very next frame either way.
