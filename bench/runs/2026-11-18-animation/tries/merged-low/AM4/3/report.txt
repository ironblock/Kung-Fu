I created `src/mix-all.ts` which builds two separate `AnimationManager` instances — one for the character's glTF groups (with `enableAnimationBlending` so bone weights mix) and one for the HUD property groups (with `enablePropertyAnimationBlending` so property weights mix) — then `step` drives both with the same delta. I was not sure whether `enableAnimationBlending` on the character manager suppresses node-target writes for weight-1 groups (note 35 mentions it doesn't write node targets for weight ≠ 1), but since the character's animation goes through the skeleton/bone-matrix path rather than node targets, I believe the bones will mix correctly; if the character also animates non-skeleton nodes via node targets, those particular nodes would not be written under the blending handler.
