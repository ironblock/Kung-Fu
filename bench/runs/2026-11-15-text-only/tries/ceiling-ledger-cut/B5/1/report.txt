I wrote /home/user/work/b06f35/app/src/label-position.ts. It takes the library's view and projection matrices, puts the point through them, and ignores clip-space depth, so points past the far plane still count as visible. A point is visible only if its view-space depth is positive (in front of the camera) and its x and y land inside the -1..1 picture square. `x` and `y` are always filled in, even off-screen, and are scaled to the canvas's CSS size (`clientWidth`/`clientHeight`) with y pointing down. Nothing has been compiled or run, because the library isn't on this machine and there are no other source files in the app to compare against.

Things I'm not sure of, because the ledger doesn't cover them (its rows are about caching, ortho, frame hooks and viewports, not projection API signatures):

- **Import and signatures:** I assumed `getViewMatrix(camera)` and `getProjectionMatrix(camera)` are exported from the root of "@babylonjs/lite" and take only the camera. The ledger only says functions with those names exist under src/camera. If `getProjectionMatrix` needs an aspect ratio or a render target, the call has to change.
- **Aspect ratio:** I'm assuming the projection matrix already uses the canvas's aspect ratio.
- **Matrix format:** I assumed Babylon's matrix layout and a left-handed camera looking down +z. That fits the ledger's checked rows (it builds the view with `writeLookAtWorldMat4LHIntoBuffer`, and switching ortho off zeroes elements 12, 13 and 15). The code accepts the matrix either as a bare 16-number array or as an object holding one in `.m`. A right-handed scene would break the in-front test.
- **Floating origin:** if a camera has `_useFloatingOrigin` on, its view matrix may be relative to a shifted origin rather than true world space, and labels would be offset. The ledger doesn't say.
- **Orthographic cameras:** they should work, but only if the camera was set up with `enableOrthographicCamera`. That's the ledger's unchecked note: assigning `camera.ortho` by hand leaves the picture perspective.
- **Canvas size:** `clientWidth`/`clientHeight` include padding. If your canvas has CSS padding, positions will be slightly off.
