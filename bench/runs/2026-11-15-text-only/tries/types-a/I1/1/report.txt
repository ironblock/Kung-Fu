Basis: the doc comment on interpolateArcRotateCamera (camera-api.d.ts, lines ~190-211) says the transition rejects when anything other than this interpolation changes the pose between frames: user drag/zoom/pan, decaying inertia, a direct pose write, or a superseding interpolation. - (a) The coasting inertia is discarded by the interpolation's own first frame, so no outside change is seen and the promise resolves. The user touches nothing after the call.
- (b) A mouse drag is a user pose change, so the promise rejects.
- (c) A second goHome() call is a superseding interpolation on the same camera, so the first call's promise rejects. Because goHome() awaits it, the first call will throw unless it is caught.
