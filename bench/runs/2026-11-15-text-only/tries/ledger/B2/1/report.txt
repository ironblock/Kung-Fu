What the ledger does establish (from `run` rows and `is` notes, which I treat as unverified):
- Motion is applied in a per-frame hook. attachControl's scene argument is optional, but without a scene the arc-rotate input only builds offsets that are never applied. So the scene must be passed.
- The control disposer must be called by us. disposeScene does not remove canvas listeners.
- Writes to beta directly bypass the clamp that the inertia step applies near 0 and π. Any change that writes alpha or beta itself must clamp beta.
- Our per-frame hook would run before the library's inertia step, so it sees the pose from the previous frame.
- Extra alpha/beta writes between frames would look like external motion to interpolateArcRotateCamera, which rejects its promise. The same writes would also double any flight or interpolation motion, which is not what you asked for.

2. Without that, a head-of-frame hook that re-applies last frame's pose change (pose minus what we last wrote) doubles the library's motion.
