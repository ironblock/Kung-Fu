I wrote /home/user/work/9cd94f/app/src/chase-camera.ts. It makes the camera with `createBankedFreeCamera`, puts it at `eye` looking at `target`, and starts it upright using world up with the part along the line of sight removed. Each `bank(up)` call does the same thing to the car's up and writes the result into the camera's `upVector`. When up points along the line of sight, either way (I count anything within 1e-6 as that), it changes nothing, so the camera keeps looking at the target with its previous roll. Nothing was compiled or run, since the library isn't on this machine.

Things I'm not sure of:
- **API guesses:** The ledger names `createBankedFreeCamera` and nothing else about it. I guessed it takes no arguments, returns a `FreeCamera` (`position`, `target` and `upVector` fields) and actually uses `upVector` for roll. If any of that is wrong, the compiler will say so, because I added no casts.
- **Roll might not refresh:** Only an unchecked note says writing to the banked camera's `upVector` triggers a redraw. A checked row counts exactly three self-tracking vector fields (ArcRotate target, FreeCamera position and target), which suggests `upVector` is not one of them. So setting it may not refresh the view while the camera stands still. Check this first when you have the library.
- **Looking straight up or down:** If the camera starts out looking exactly up or down, "upright" has no meaning, so I fall back to +Z for the starting roll.
