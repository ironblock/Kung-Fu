I wrote /home/user/work/9b808a/app/src/limited-orbit.ts. It calls `attachControl(camera, canvas, scene)` to get the library's drag, wheel and pinch controls. It also adds a clamp on `camera.radius` (the camera's distance from the point it orbits) that runs every frame, and fixes the radius right away if the camera starts out of range. The returned function removes the controls and the clamp. None of this has been compiled or run, since the library isn't on this machine.

**Why the clamp is added to the scene's list directly:** I add it to the end of the scene's internal `_beforeRender` list after `attachControl`, instead of using `onBeforeRender`. Checked ledger rows show that `onBeforeRender` puts callbacks at the front of that list, that `attachControl` adds its per-frame step to the end, and that the scene runs the list front to back. So a clamp added with `onBeforeRender` would run before that frame's zoom step, and some frames could be drawn out of range.

**Why not `setCameraLimits`:** the only description of what it does is an unchecked note, and the ledger never gives its arguments, so I couldn't be confident it would compile or clamp zoom as intended.

**Other choices in the code:**
- It also sets the camera's `lowerRadiusLimit` and `upperRadiusLimit` fields to the range and puts the old values back on removal. They don't limit anything on their own, but an unchecked note says `interpolateArcRotateCamera` reads them. If so, an animated move won't fight the clamp and fail.
- It throws a `RangeError` unless 0 <= `minDistance` <= `maxDistance` and both are finite.

**What I'm not sure of:**
- That `attachControl` takes `(camera, canvas, scene)` in that order and returns a function that removes its listeners. The ledger mentions the returned function only in an unchecked note.
- That the scene object really has a `_beforeRender` array. Checked rows show the library uses it, but it is internal, so the code reaches it through a type cast.
- If a camera hook attached later (after this function) changes the radius in the same frame, it would run after the clamp.
- If the removal function is called in the middle of a frame (for example from an `onBeforeRender` callback), taking the clamp out of the list could make the scene skip the hook after it for that one frame.
