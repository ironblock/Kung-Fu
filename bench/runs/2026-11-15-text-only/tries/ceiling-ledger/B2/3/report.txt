I wrote `/home/user/work/6c1355/app/src/fast-orbit.ts`. It calls the library's `attachControl`, then puts two small hooks in the scene's per-frame list, one just before and one just after the hook `attachControl` adds. The "after" hook looks at how much the default controls changed `alpha` and `beta` in that frame and applies the same change once more. That doubles left-right and up-down turning, including the glide after release. Radius (wheel and pinch zoom) and pan are never touched. The returned function takes both hooks out of the list and then calls the library's own cleanup, which removes its canvas listeners and its per-frame hook. None of this has been compiled or run, because the library isn't on this machine.

Things I'm not sure of:
- **The `attachControl` signature.** I called it as `attachControl(camera, canvas, scene)`. The ledger only says it takes a scene argument and returns a cleanup function; it never gives the argument order or any options. I also don't know if there's a built-in sensitivity option, so I didn't guess one.
- **Using a private field.** The code reaches into `scene._beforeRender`, which isn't public. The checked ledger rows confirm that the controls add their hook to the end of that list and that the list runs front to back. My placement depends on that, and an internal change in a later release could break it. If the new hook can't be found, the function throws instead of failing silently.
- **Poles and wrap-around.** I don't know where the default controls stop the camera at the top and bottom. My extra turn keeps `beta` just inside 0 to pi, so it could go slightly past a stop the defaults use. I also assumed the controls may wrap `alpha` and allowed for that.
- **Removing the controls during a frame.** If you call the returned function from inside a per-frame callback, removing items from the list can make the scene skip one other callback that frame. The ledger notes the library's geospatial fly has the same effect when it ends.

One thing for you to decide: the ledger says `disposeScene` doesn't clean up canvas listeners. You'll still need to call the returned function yourself, or hand it to `onSceneDispose(scene, cleanup)`.
