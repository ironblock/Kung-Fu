I wrote /home/user/work/18a9b6/app/src/label-position.ts. It multiplies the point by the camera's view-projection matrix and turns the result into CSS pixels using `clientWidth`/`clientHeight`. Front or behind comes from the sign of clip-space w. Inside the picture means x and y are both within -1..1 after dividing by w. Depth is never checked, so points beyond the far plane still count as visible. I couldn't compile or run it, because the library isn't on this machine and the `../babylon-lite` path in tsconfig doesn't exist.

Things I was not sure of:
- **The getter.** The ledger names `getViewProjectionMatrix` and says it refreshes its cached matrix when fov, near or far change. It does not give the signature. I assumed it is a value export called as `getViewProjectionMatrix(camera)` that returns either a 16-number array or an object with `.m`. If it also takes an aspect ratio, or the canvas aspect has to be set somewhere else, that call needs changing.
- **Matrix layout.** I assumed Babylon's flat row-vector layout: translation in entries 12–14 and the perspective w term in 11. This fits the ledger's note that the perspective writer fills 0, 5, 10, 11 and 14, but that note is unchecked.
- **Orthographic cameras.** In ortho mode w is always 1, so it can't tell front from behind. There I fall back to the direction from `camera.position` to `target` (or `center` for the globe camera). That is a guess about each camera's fields. If a camera has neither, every point counts as in front.
- **Points behind the camera.** The spec doesn't say what `x` and `y` should be for these. I divide by the absolute value of w, so the position stays on the side the point is really on, which works for an arrow. These points are always reported as not visible.
