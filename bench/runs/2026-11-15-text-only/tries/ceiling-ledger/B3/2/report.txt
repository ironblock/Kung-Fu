I wrote `/home/user/work/4aed24/app/src/fly-controls.ts`, but it has never been compiled or run, and parts of it rest on guesses about the library. `attachFlyControls` attaches the library's `attachFreeControl(camera, canvas, scene)`. To make Shift a speed key only, it stops Shift key events aimed at the canvas before the library's listeners can see them. For the 3x boost, a per-frame hook runs after the library's movement and triples whatever position change the library made that frame while either Shift is held. The returned function removes the library controls, our listeners and our hook.

What I was not sure of:
- **Nothing about free-camera key bindings or speed is in the ledger, and the library isn't on this machine.** So I don't know whether `attachFreeControl` binds Space and PageDown by default, whether it has a speed setting, or whether it uses Shift for "down" itself. Please check that Space and PageDown work. If they don't, `attachConfigurableFreeControl` probably takes key options, but I couldn't see its signature.
- **The boost hook goes straight onto the internal `scene._beforeRender` list (through a type cast).** The ledger says that is the only way to run after the camera has moved; `onBeforeRender` runs before it. The downside is that a position you set by hand, for example from an `onBeforeRender` callback, also gets tripled while Shift is held.
- **Shift is blocked well enough unless the library reacts to Shift in one of two ways I can't block.** One is reading `e.shiftKey` on other keys. The other is listening in the capture phase on window, registered before us. Also, other code on the page that listens for Shift won't receive Shift presses made while the canvas has focus.
- **The returned function removes the hook with a splice.** Like the library's own remove functions, calling it from inside a per-frame callback would skip the next callback for one frame.
