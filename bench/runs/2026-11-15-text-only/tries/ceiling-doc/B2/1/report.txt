I wrote /home/user/work/4b1fad/app/src/fast-orbit.ts. It calls the library's own `attachControl(camera, canvas, scene)` and wraps it with two small `pointermove`/`touchmove` listeners on the canvas, one added before and one after. Together they measure how much the library's drag handler adds to `inertialAlphaOffset`/`inertialBetaOffset` on each move and add that amount again, so each drag turns twice as far on both axes. The glide is doubled too, because it comes from those same offsets winding down each frame. The wheel, panning and pinch-zoom change other values, so they stay exactly as the library does them. The returned function removes my listeners and calls the library's own cleanup, and nothing of mine runs each frame. Nothing was compiled or run, since the library isn't on this machine.

Things I wasn't sure of:
- **No speed option.** The library's notes list no rotation-speed setting for `attachControl` (the 1000 divisor is fixed inside it), so this workaround is my own approach.
- **Unconfirmed assumptions about the library's code.** It assumes the library listens for drag movement on the canvas itself (not on `window` or `document`), and that its handler doesn't call `stopImmediatePropagation`. If either is wrong, drags would turn at the normal speed rather than twice as far.
- **The glide's tail ends slightly early.** The library stops the glide once its value drops below a small cutoff. Because the doubled value starts higher, it takes a frame or so longer to get there, so the glide comes out about 2x rather than exactly 2x.
