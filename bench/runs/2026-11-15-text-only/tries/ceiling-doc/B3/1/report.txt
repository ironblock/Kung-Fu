I wrote `/home/user/work/4a9f2e/app/src/fly-controls.ts`. It does not move the camera itself: it calls the library's `attachConfigurableFreeControl` with Space as the only rise key, PageDown as the only sink key, and both Shift keys as boost keys with a multiplier of 3. It returns the library's own cleanup function, which the notes say removes every canvas listener and the per-frame hook; mine also does nothing if it's called a second time. Nothing has been compiled, run or tested, because the library isn't on this machine.

Three things I wasn't sure of:
- **The Shift fix depends on one sentence in the notes.** The library's default controls use Shift to move down. I took it out because the notes say `upKeys`/`downKeys` *replace* the default vertical keys rather than add to them. If they actually add to them, holding Shift would still sink the camera. It's worth a quick check in the browser: hold Shift with nothing else and make sure the camera stays put.
- **I don't know which key names the library expects.** The notes don't say whether these lists are matched against `KeyboardEvent.code` (`"Space"`, `"ShiftLeft"`) or `KeyboardEvent.key` (`" "`, `"Shift"`). So each list includes both spellings, and whichever one the library doesn't use just never matches. Once you know which it is, you can drop the extra ones.
- **Not checked against the library itself:** I assumed `attachConfigurableFreeControl` is exported from the package root `"@babylonjs/lite"`, and that `fastMultiplier` scales movement speed only, not mouse-look.
