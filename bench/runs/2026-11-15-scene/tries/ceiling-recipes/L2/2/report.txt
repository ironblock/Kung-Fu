I wrote `/home/dev/6ffc71/app/src/lamps.ts`. `addLamp` makes the warm lamp with `createClusteredPointLight` (colour `[1, 0.85, 0.6]`, intensity 1, `range` set to `reach`), makes sure it's in `lamps.pointLights` exactly once, and calls `markClusteredLightContainerDirty(lamps)` so the next frame picks it up. It doesn't re-register the container or touch the other lamps. Nothing has been compiled or run, because the library isn't on this machine.

Things I wasn't sure of:
- **Does the light list grow?** This is the main open question. The declarations don't say whether the lights' GPU data can grow past the number of lamps that existed at startup. If the renderer doesn't grow it on its own, lamps added by clicking won't show up, and only the library's source or a real run can tell you. There's nothing in the declarations to rebuild it with.
- **Does creating a lamp add it to the list?** The declarations don't say whether `createClusteredPointLight` already puts the lamp into `lamps.pointLights`. The code adds it only if it's missing, so either way it isn't counted twice, which would make it twice as bright.
- **Extras you didn't ask for:**
  - `addLamp` throws a `RangeError` if `reach` isn't a positive finite number or `position` isn't three finite numbers. It checks before changing anything, so bad input can't break later frames.
  - It copies `position` rather than storing your array, so changing that array later won't move the lamp.
