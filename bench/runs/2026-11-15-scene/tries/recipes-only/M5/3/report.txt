I wrote `/home/dev/972e27/app/src/forest.ts`. `removeTree` walks `treeIds` from the end, and for each entry equal to `id` it calls `removeThinInstance(forest, i)`, copies the last id into slot `i`, and pops the array. Going from the end means a moved entry is never one that still needs removing, and an id that isn't in the list changes nothing.

I could not run or type-check this, since the library isn't on the machine. I'm relying on the swap-with-last behaviour of `removeThinInstance` described in your recipes file, and I assumed `removeThinInstance` is exported from `"@babylonjs/lite"`. I also assumed the mesh's instance count matches `treeIds.length` and that one tree can have several instances, which the loop handles.
