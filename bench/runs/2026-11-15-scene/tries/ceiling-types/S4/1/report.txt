I wrote `src/crate-field.ts`. It makes one 1-unit box, gives it one plain translation per crate in your order, turns on the library's `enableThinInstanceWorldBounds` so the sun's shadow map is fitted around every crate rather than just the origin, then adds the mesh to the scene and returns it. Nothing has been compiled, tested or run, since the library isn't on this machine.

Things I wasn't sure of:
- **Shadow coverage:** the declarations disagree on whether the shadow fit already counts every crate. One comment says it does. The existence of the opt-in suggests that for meshes built by hand like this one, it might not. I turned the opt-in on so both cases are covered. If the fit turns out to ignore crate positions entirely, shadows would only cover the origin and the approach would need changing.
- **Very spread-out yards:** sideways, the shadow map is fitted to the crates. It isn't clear whether depth along the sun's direction is fitted too, or fixed at the sun shadow settings' defaults of 1 to 10000 from the light's position. If it's fixed, crates very far along that direction, or behind the light's position, could still be cut off. That is set in your sun code, not in this file.
- **Material:** the declarations say a box needs a material before it's added to the scene. Your signature has no material and the file doesn't describe how to make one. So I added an optional fourth `material` argument, which is set before the mesh is added. Calls with three arguments still work, but if no material is passed, the add may fail or draw nothing.
