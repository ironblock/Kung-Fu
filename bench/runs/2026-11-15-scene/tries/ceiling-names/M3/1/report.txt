I wrote `/home/dev/4af6c6/app/src/remove-keep.ts`, but it has never been compiled or run, since the library isn't on this machine. The function first unhooks each child mesh from the removed mesh with `setParent`, and if the child moved, puts it back where it was. Only then does it call `removeFromScene` on the mesh. Removing the mesh probably takes its attached meshes with it, which is why the children are unhooked first; if any kept mesh still ends up missing, it is added back once.

Things I wasn't sure of:
- **Where the kept meshes go:** they get the removed mesh's own parent. For a table with no parent that means no parent at all, which matches what you described. If a table sits inside a group, the lamp stays in that group rather than moving to the top level. If you always want no parent, change `newParent` to `null`.
- **Library behavior I assumed:** that `setParent` updates the table's `children` list, and that matrices are 16 numbers with the translation in elements 12–14. I also assumed `position`, `rotationQuaternion` and `scaling` accept `.x/.y/.z/.w` assignments. A type check against the real library will catch the last one if it's wrong.
- **Stretched-and-rotated case:** if `setParent` doesn't keep the world position itself, my backup rebuilds position, rotation and scale. That can't exactly reproduce a mesh that is rotated on a parent stretched by different amounts along each axis, so such a lamp would come out slightly off.
- **Non-mesh children:** children that aren't meshes in the scene's mesh list, such as empty group nodes, are not kept. They go away with the removed mesh, as your description implies.
