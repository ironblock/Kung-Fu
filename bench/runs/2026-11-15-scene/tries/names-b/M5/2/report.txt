I wrote `/home/dev/f1f3af/app/src/forest.ts` with `removeTree`. It finds every instance whose id matches, rebuilds the thin-instance matrices and colors without them using `setThinInstances` and `setThinInstanceColors`, and rewrites `treeIds` in place to the same order. If the id isn't present, it returns without changing anything. I did not run or type-check it, because the library isn't on this machine.

I didn't use `removeThinInstance` because the declarations don't say whether it shifts later instances or swaps the last one into the gap. Rebuilding avoids depending on that. The main things I'm unsure of:

- **Instance count:** I treat `thinInstances.count` as the number of instances drawn. If `setThinInstanceDrawCount` can make the drawn count smaller, that case isn't handled.
- **Layout:** I assume 16 floats per matrix and 4 per color.
- **Imports:** I assume `setThinInstances` and `setThinInstanceColors` are exported from the package root.
- **Duplicates:** If the same id appears more than once, every instance with that id is removed.
- **Cost:** Each removal copies the whole buffer, which is fine for a viewer but would be slow for very large forests.
