I wrote `/home/dev/e16034/app/src/mist.ts`. Its `addMist(scene)` calls `setFog(scene, …)` with a new linear fog config each time: clear up to 30 units, fully fogged from 120, colour `[0.75, 0.8, 0.88]`. Per note 8 in `scene-notes.md`, setting `scene.fog` directly writes nothing before the first `setFog`, and editing an existing fog object only reaches the shaders when the camera or aspect changes. Calling `setFog` with a new object is the way the notes give for the values to arrive on the next frame. I haven't compiled or run it, since the library isn't here.

Things I'm not sure of:
- **The fog config's field names are a guess.** The declarations use `FogConfig` but its definition (in `material/standard/standard-material`) isn't in `scene-api.d.ts`. I guessed Babylon-style names: `mode: "linear"`, `start`, `end`, `color`. I typed the object from `setFog`'s own parameter, so if the guess is wrong the compiler will flag it rather than fail silently. Please check those names against the real type.
- **Materials built before the mist is added might not use it.** The declarations hint that standard-material shaders may only include fog code if fog was set when they were built. The notes don't say whether adding fog later needs `rebuildSceneRenderables(scene)`, so I didn't add that call. The safest option is to call `addMist` before the scene is registered or built. If you call it later and see no mist, a rebuild is the likely fix.
