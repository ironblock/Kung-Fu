I wrote `src/remove-keep.ts`. It saves each child's world matrix first, then uses `setParent` to move each child to the deleted mesh's own parent (or to no parent if it had none). It then writes a new position, rotation quaternion and scaling so the child stays where it was in the world, and finally takes the mesh out of its parent and calls `removeFromScene`. Nothing is added back to the scene, so each kept mesh is still listed exactly once. I couldn't compile or run any of this, because the library isn't here.

Things I wasn't sure of:
- **Where the kept meshes go:** if the table sits under something else, like a room node, the lamp and vase move under that node rather than to the top of the scene. That keeps them in the room's hierarchy. If you'd rather they always end up at the top, it's a one-line change.
- **Things the declarations don't cover:** I assumed `worldMatrix` is 16 numbers laid out as in Babylon.js, with the translation in elements 12–14. I also assumed `position`, `rotationQuaternion` and `scaling` have writable `x`/`y`/`z`/`w`. Neither type is in `scene-api.d.ts`. The docs also don't say whether `setParent` keeps the world or the local transform, so the code works either way.
- **Skew:** if the table is scaled unevenly (say, wider than it is deep) and a lamp on it is rotated, the lamp is slightly skewed in the world. Position, rotation and scaling can't express that, so the lamp keeps its position and size but loses the skew.
- **Lights and leftovers:** lights attached directly to the table are kept too. A child that had already left the scene but was still listed under the table is removed along with it.
- **Undo:** the library disposes the removed table (notes 1 and 23), so it can't be added back later. An undo would have to create a new mesh, or hide the table with `setMeshVisible` instead of removing it.
