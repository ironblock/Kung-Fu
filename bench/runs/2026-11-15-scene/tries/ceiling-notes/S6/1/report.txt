I wrote `/home/dev/a0fb2e/app/src/ramp.ts`. `createRamp` builds the five-face wedge from 18 vertices, each face with its own outward normals, then creates the mesh with `createMeshFromData`, adds it to the scene and returns it. It also throws a `RangeError` if width, length or height isn't a positive number. Nothing has been compiled or run, since the library isn't on this machine.

Things I wasn't sure of:
- **Which side gets drawn:** the declarations and notes don't say which triangle winding the library treats as the front, and getting it wrong would make the ramp look inside out. So the code doesn't guess: it checks the library's own box data (`createBoxData()`) once and winds the ramp's triangles the same way. This assumes the box's normals point outward, and that `createBoxData` and `createMeshFromData` can be imported from `"@babylonjs/lite"` itself. Your declarations list them, but I couldn't see the package's main export list.
- **Material:** the ramp has no material, like the library's own `createBox`. Note 32 says it will be in `scene.meshes` but won't be drawn until you set `mesh.material`, which then queues it for a build. Nothing in the declarations covers creating a material, so I didn't add one.
