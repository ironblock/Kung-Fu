I wrote `/home/dev/ab4ab6/app/src/crate-field.ts`. It builds a 1-unit box, gives it one thin instance per centre (a plain translation, in the order given), and then calls `enableThinInstanceWorldBounds(mesh)` before adding the mesh to the scene. That last call is what keeps distant crates inside the shadow map. The notes say the map only covers the box around its casters' bounds, and without that call the bounds would be those of a single crate. Nothing has been compiled or run, since the library isn't here.

Things I wasn't sure of:

- **Material:** The shape factories leave the material empty, and the notes say a mesh added without one never gets drawn. The declarations don't show how to create a material, so I added an optional fourth parameter, `material`, which is set before the mesh is added to the scene. Your three-argument calls still work, but the crates will probably only show up and cast shadows if you pass a material.
- **`enableThinInstanceWorldBounds`:** Nothing describes what it does. I'm assuming from its name, and from the bounds hooks in the declarations, that it makes the mesh's bounds include every instance and that the shadow fitting uses them.
- **Matrix layout:** I put the translation in elements 12–14 of each matrix, as Babylon does. The declarations don't confirm that.
- **Shadow depth:** The mesh's bounds only set how wide the shadow map is. How deep it reaches along the sun's direction is set separately on the sun (`orthoMinZ`/`orthoMaxZ`, 1 to 10000 by default, measured from `light.position`). Your sun code has to keep the light's position behind all the crates and that range long enough to reach them.
