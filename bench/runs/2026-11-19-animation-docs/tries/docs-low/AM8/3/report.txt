Without blending enabled, each property group writes its sampled value directly to the target in the order the groups appear in the manager's task list, so the last group to tick wins. Re-adding A (or adding a second A group) moves it to the end of that list, making its write the final one and giving `x = 10`; the initial setup and the clear-then-B-then-A scenario both leave A last, while the original order leaves B last (`x = 30`).

I was not uncertain about anything here — the "last-write-wins" semantics without blending are unambiguous from the docs, and `addAnimationGroup` appends to the end of the task list (which is what makes re-adding a group change the write order).
