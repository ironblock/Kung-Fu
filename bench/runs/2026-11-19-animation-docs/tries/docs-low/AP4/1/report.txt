I wrote `src/release.ts` which iterates every group on the manager via `getAnimationGroups`, checks each group's `targetedAnimations` for a matching `(target, path)` pair by reference equality and string equality, and calls `stopAnimation` on any group that matches — stopping is used rather than pausing because a paused group still evaluates and rewrites its targets on tick, whereas a stopped group's `tickAnimation` returns immediately, guaranteeing nothing writes to the property afterward. I was not sure whether the weighted property mixer (`_propertyMixer`) could still sample a stopped group's tracks through some internal path, but the doc states the mixer "advances group time" per group and the STOPPED state causes `tickAnimation` to return immediately, so a stopped group should be inert in both the direct and mixer paths.
