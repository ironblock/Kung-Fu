I created `src/play-again.ts` which calls `stopAnimation` to reset the group to frame 0 (clearing the stopped/finished state) and then `playAnimation` to start it playing again from the beginning at its existing `speedRatio`; since `loopAnimation` is already `false` on a one-shot, it will run to its end once more and stop, ready for another press. I'm confident in this approach; the only thing I couldn't verify at runtime is whether `playAnimation` is guaranteed to clear `_stopped` from the STOPPED state (the state machine diagram implies it does), but the documented STOPPED → PLAYING transition via `play()` makes that the expected behavior.
