I created `src/play-again.ts` which calls `stopAnimation` (resetting the group to frame 0 and the STOPPED state) followed by `playAnimation` (transitioning to PLAYING), so the clip restarts from its first frame at its own `speedRatio` and runs to its end once more. I'm not 100% certain whether `playAnimation` clears the `_stopped` flag internally or whether an explicit reset is needed — the state-machine diagram in the docs shows STOPPED → PLAYING via `play()`, so I'm trusting that, but if the implementation doesn't clear `_stopped` on play, an additional `group._stopped = false` would be required.
