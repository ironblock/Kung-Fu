I created `src/pulse.ts` which builds a non-looping property-animation clip (scale 1→1.5→1 over 0.4 s, linear) and a corresponding group added to the shared manager; the returned press-handler resets the group's time to zero and calls `playAnimation`, so every press—whether the previous pulse is still running or already finished—restarts the pulse from the beginning, and nothing moves until the first press. I was not fully certain whether calling `playAnimation` on an already-playing group is a guaranteed no-op versus a reset, but since we explicitly set `currentTime = 0` immediately before, the next manager tick will evaluate from the first keyframe regardless.
