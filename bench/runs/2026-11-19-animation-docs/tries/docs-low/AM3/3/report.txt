I created `src/skip-ahead.ts` which delegates to `updateAnimationManager(manager, ms)` — the library's own public stepping function — so all animation groups, generic tasks, weight-fade jobs, and category handlers (weighted mixers) advance by exactly `ms` in one call, and no structural state (including `fixedDeltaMs`) is touched, so the manager resumes its normal fixed-step cadence on the next frame. I wasn't sure whether your game loop also invokes `onUpdate` separately after its own `updateAnimationManager` call; if so, the skip will fire `onUpdate` once extra (once for the skip), which should be harmless but worth knowing about.
