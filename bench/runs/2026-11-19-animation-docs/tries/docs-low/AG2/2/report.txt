I implemented `freezeForPosing` by removing the group from its owning `AnimationManager` (so `tickAnimation` is never called and no pose writes reach the nodes), pausing it, and capturing `currentTime`. The returned `resume` restores the saved time, re-adds the group to the manager, and calls `playAnimation` so it continues at its existing `speedRatio`. One thing I was not sure of: whether `_animationManager` is always populated when a group is driven by a scene's render loop versus a standalone manager — if it happens to be undefined in your setup, the freeze would rely on pause alone, which per the docs still evaluates (rewrites) the pose each tick, so manual node changes would be overwritten. If that turns out to be the case in practice, you'd need an additional seam (e.g. a flag the scene checks before ticking groups) to fully suppress writes.
