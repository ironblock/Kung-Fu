I created `src/hand-over.ts` which registers a per-manager animation task that linearly ramps `from.weight` from 1→0 and `to.weight` from 0→1 over `durationMs`, skipping the first frame so the next render shows `from` alone; a new call cancels the previous task (via a `WeakMap`) and restarts the blend from the new pair's initial state. I'm not fully certain whether the "next frame shows `from` alone" requirement means the first task tick should be skipped entirely (my choice) or merely that the tiny first-frame delta is negligible in practice — if your frame loop calls `updateAnimationManager` *before* rendering and you'd prefer the blend to start on that same first tick, remove the `firstFrame` guard.
