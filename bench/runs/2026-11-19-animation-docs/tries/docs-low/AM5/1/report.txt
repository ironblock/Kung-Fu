I created `src/watched-manager.ts` which builds a standard `AnimationManager` and registers a single uncategorised task whose update callback invokes `onStep` with the delta the manager passes to tasks, so every `updateAnimationManager` call produces exactly one `onStep` step. Because the task carries no category, it is untouched by the `animation-group` category handler that weighted blending and fades install, so it keeps firing regardless of how the manager's groups are later mixed. I was not sure whether the `onUpdate` option on `AnimationManagerOptions` is also invoked during caller-driven `updateAnimationManager` calls (the doc describes it as "autonomous tick" only), so I avoided relying on it and used a task instead, which is guaranteed to be dispatched on every update.
