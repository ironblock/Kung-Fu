I created `src/set-share.ts` which sets the group's weight to `share` via `setAnimationWeight` and then scans `manager.animations` for any in-progress fade task that references this particular group, removing it so it cannot overwrite the weight on later frames; fades on other groups are left untouched. I'm not fully certain of the exact property name the fade implementation uses to store the group reference on its task object, so I check the four most likely names (`group`, `_group`, `targetGroup`, `_targetGroup`); if the real name differs, the weight will still be set immediately but the old fade would survive one or more frames.
