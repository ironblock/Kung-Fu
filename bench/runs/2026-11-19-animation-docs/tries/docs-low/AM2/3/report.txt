I set the weight immediately via `setAnimationWeight`, then call `fadeAnimationWeight` with a zero-duration fade from `share` to `share`, which replaces any in-progress fade task for this group (the standard replace-on-call pattern) while leaving other groups' fades untouched. I was not fully certain that `fadeAnimationWeight` replaces a prior fade for the same group rather than stacking a second task — if it stacks, the old fade would still overwrite the weight on subsequent frames, and the function would need to locate and remove the stale task from `manager.animations` directly instead.
