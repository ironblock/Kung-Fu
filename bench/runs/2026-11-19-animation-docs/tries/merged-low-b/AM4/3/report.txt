I created `src/mix-all.ts` which sets up two separate `AnimationManager` instances—one for the character glTF groups with `enableAnimationBlending` (so weighted mixing applies to bones) and one for the HUD property groups with `enablePropertyAnimationBlending` (so weighted mixing applies to HUD properties)—because per your notes those two functions share a single slot on a manager, so a single manager can't provide both. `step` advances both managers by the given delta each frame. I'm not entirely sure whether the character groups' bones will also be written correctly when their weights are all at 1 (i.e., no blending needed), since note 35 only describes the behaviour *under* `enableAnimationBlending` with weight ≠ 1; the default full-weight path should still write normally, but I couldn't verify that without running the library.
