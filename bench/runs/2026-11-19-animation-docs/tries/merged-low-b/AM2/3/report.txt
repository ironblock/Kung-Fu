I set the weight immediately via `setAnimationWeight`, then call `fadeAnimationWeight` with a 1 ms fade from the current weight (now `share`) to `share`, which replaces any in-flight fade task for this group with a no-op that self-removes after one tick—so the weight stays at `share` on every subsequent frame, other groups' fades are untouched, and a later `fadeAnimationWeight` call on the same group works as usual. I was not sure whether the library tolerates `durationMs: 0` (a zero-division in the progress calculation could yield NaN on a zero-delta update), so I used 1 ms as a safe minimum; functionally it is indistinguishable from instant because `from` equals `to`.
