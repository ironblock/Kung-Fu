I wrote `src/beacon.ts` using a custom `AnimationTask` that accumulates elapsed time, computes the phase within each period via modulo, and writes the linearly rising/falling intensity scaled by the current strength to `lamp.intensity` on every update. The returned closure simply reassigns the strength variable, which takes effect on the next update without touching the timing, so the rhythm is unaffected and multiple beacons on the same manager each run as independent tasks. I was not sure whether the caller might pass a strength outside (0, 1] and chose to store it as-is rather than clamp, trusting the stated contract.
