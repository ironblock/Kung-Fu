I wrote `src/pulse.ts` which builds a single non-looping property-animation clip (keys at 0 s → 1, 0.2 s → 1.5, 0.4 s → 1, linear) on the button's `scale` path, creates it on the shared manager, pauses it with `goToFrame` so it is idle until pressed, and returns a function that calls `goToFrame(group, 0)` + `playAnimation(group)` — the `goToFrame` immediately writes scale 1 and resets the clock, and `playAnimation` clears any stopped/finished state so every press (first, mid-pulse, or after completion) restarts the pulse from the beginning.

I was not sure whether "at once" in the spec required the starting value to be written synchronously inside the press handler versus on the next `updateAnimationManager` call; I chose `goToFrame` specifically because it writes the value immediately, which also gives the nice visual snap-back-to-1 when a press lands mid-pulse.
