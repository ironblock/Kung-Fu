I created `src/pulse.ts` which builds a non-looping property-animation group (keys at 0 s → 1, 0.2 s → 1.5, 0.4 s → 1 on the `scale` path), stops it immediately so nothing moves before the first press, and returns a function that calls `stopAnimation` then `playAnimation` to restart the pulse from the beginning on every press—whether it arrives mid-pulse or after the group has already finished.

The one thing I was slightly unsure of is whether `createPropertyAnimationGroup` defaults `fromTime` to 0 and `toTime` to the clip's duration when neither is passed; the notes confirm that `toTime` must exceed `fromTime` or creation throws, and that the clip duration here is 0.4 s, so the defaults should satisfy that constraint. If the library instead defaults both to `undefined` and throws, passing `{ fromTime: 0, toTime: 0.4 }` explicitly would be the fix.
