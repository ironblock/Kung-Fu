I created `src/skip-ahead.ts` exporting `skipAhead`, which advances every group's `currentTime` by `ms/1000 * speedRatio` (wrapping looping groups via modulo), calls each active task's `_update` with the full `ms`, and respects the manager's `_preUpdate` hook and category-handler gate—so after the call the manager's next frame (fixed-step or not) proceeds exactly as if nothing special happened. The one thing I'm not fully certain of is whether weight-fade internals are always stored as plain tasks in `manager.animations` versus some hidden bookkeeping on the manager itself; if Babylon Lite keeps fade state outside the task array, those fades would not be advanced by this function.
