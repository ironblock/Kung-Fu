I set `group.currentTime` to `group.duration` so the progress bar reads 100%, then called `pauseAnimation` to stop playback. Because a paused glTF group still writes its pose at `currentTime` on every update (per your notes), the model holds the final keyframe values on every subsequent frame without advancing.

The one thing I was not fully certain of: whether evaluating a *looping* glTF group at exactly `duration` yields the last keyframe values or wraps to the first (note 10 mentions wrapping "on an update landing exactly on the range end"). I reasoned that the modulo wrap happens during time *advancement* in the tick, not during the sampler evaluation itself, so a paused group evaluating at `duration` should produce the last keyframe values. If in practice the evaluation also wraps, you'd need to set `currentTime` to a value just shy of `duration` (e.g. `duration - 1e-6`) instead.
