I wrote `src/release.ts` which resolves the parent object for the given dotted path, then iterates every group on the manager and calls `stopAnimation` on any whose `targetedAnimations` contain an entry whose `target` is that parent object and whose `path` is the final segment. Using `stopAnimation` (rather than `pauseAnimation`) guarantees the group takes no part in writing even under `enablePropertyAnimationBlending` (per note 32), so the property is fully released regardless of whether blending is active. I was not sure whether you'd prefer `pauseAnimation` (which preserves `currentTime` for later resumption) over `stopAnimation` (which resets to the start), but since the spec says "stops" and blending makes pause insufficient on its own, I went with stop.
