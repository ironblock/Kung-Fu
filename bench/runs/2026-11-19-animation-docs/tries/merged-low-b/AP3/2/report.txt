I wrote a custom `AnimationTask` that tracks its own elapsed time, computes a linear triangle-wave phase (rise over 0.5 s, fall over 0.5 s, repeating), and writes `rest + strength * 0.5 * phase` to `node.position.y` each update; the returned closure simply reassigns the captured `strength` so the next update picks it up without restarting the clock. I'm confident in the solution; the only thing I'd flag is that if `deltaMs` can ever be negative or non-finite (per note 20, the manager itself ignores those when `fixedDeltaMs` is unset), the task would accumulate a negative or NaN `elapsed`—but since you're driving the manager yourself with real frame deltas, that shouldn't occur in practice.
