I worked from the declarations you pasted, since the library source isn't available. Those declarations don't include the orbit math, so I used the standard arc-rotate formula (eye = target + r·(cos α·sin β, cos β, sin α·sin β)). Under that formula, β = -0.5 puts the eye at the same point as a fresh camera with α = π, β = 0.5, so the view matches and the up vector stays upright. The uncertainty is whether the library refreshes `worldMatrix` or `getCameraPosition` immediately after you set `beta` or only on the next frame. If it's the latter, reading the position without a frame would give the old value, (4.7943, 8.7758). Checking the library's implementation or rendering one frame would settle this.
