I wrote the file with the values the declarations support, but they are inferences, not confirmed behavior. The declarations show `interpolateArcRotateCamera` returns `Promise<void>` and takes an optional `AbortSignal`, which is the only documented way to cancel it. Since `goHome()` passes no signal, nothing in the declarations makes it reject. I could not check the library's implementation, so these answers are unverified. The declarations also don't say whether a user's drag or leftover inertia interrupts the tween, or whether a superseded first call settles at all. If it never settles, `await` hangs instead of resolving. If you want cancellation to be explicit, pass an `AbortSignal` and catch the rejection, though the declarations don't specify the rejection reason.
