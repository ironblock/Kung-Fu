I chose `attachConfigurableFreeControl` over `attachFreeControl` because the default free control maps Shift to moving down, which you ruled out. The function is a thin wrapper that passes the scene through and returns the library's dispose function, and it adds no per-frame work of its own.

I'm not sure of several things:
- I assumed `attachConfigurableFreeControl` is exported from the `@babylonjs/lite` root. Its declaration is only in `configurable-free-camera-controls.d.ts`, so the import path may need changing.
- I didn't have the library's source, so I haven't verified that the returned dispose function also removes the scene's per-frame hook. The notes don't say, and the requirement that nothing keeps running each frame depends on it.
- The notes don't say whether the configurable control keeps the default W/A/S/D and arrow bindings and the mouse-look behaviour when `upKeys` and `downKeys` are overridden. I expect it does, but this is unverified.
- Nothing has been run, and the library isn't on this machine, so the code is untested.
