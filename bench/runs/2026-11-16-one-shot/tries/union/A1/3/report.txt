I wrote this from the type declarations and notes you pasted, without the library to run against. Things I am not sure of:
- The radius nudge relies on note 3 (writes take effect only when the stored value changes) and on the library not optimising the two writes away. I could not check either.
- I assumed `Vec3` is a plain mutable `{x, y, z}`, as the declaration suggests.
- Pending inertial panning from an ongoing drag will still move the new target on the next frame. I did not clear it, since the spec did not ask for that.
- If the radius is pinned at a limit and the opposite limit is also at that value, the nudge can fail to change the stored value. This is an edge case I did not handle.
