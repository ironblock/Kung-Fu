I wrote the file from the library's declared API and the notes, and assumed several things I could not check: that `getViewMatrix`, `getViewProjectionMatrix`, `getEffectiveAspectRatio`, `getCameraPosition` and `projectWorldToScreen` are exported from the `@babylonjs/lite` root; that `projectWorldToScreen` returns y increasing downward; and that `worldOrigin` should be passed only with a floating origin. The code throws a `RangeError` if the canvas has zero size when the tracker is created, and it measures whatever the renderer draws, so a stale target (notes 2 and 3) affects both sides equally.
