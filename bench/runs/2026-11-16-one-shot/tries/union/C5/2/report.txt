The `camera.radius = 7` line is safe. It runs before the first frame, so per note 6 it becomes the start value and doesn't cause a rejection. Nothing sets a radius goal, so the radius stays at 7 (note 58).

The `spot.x = 5` line doesn't cause a rejection either, because it changes the goal, not the camera's alpha, beta, radius or target. But it is not safe if you want the flight to end at x = 1. The goal is read every frame (note 56), so the camera heads for x = 5. Reusing the scratch vector retargets the flight you just started. Give each marker its own goal object.

I'm not sure of two things:
- **finalTargetX:** The notes say alpha, beta and radius snap exactly to the goal at the end, but say nothing about target. The value 5 is therefore approximate, and the exact final value could differ slightly.
- **Whether the goal is copied or read live:** I inferred a live read from note 56. If the implementation copies the goal at call time, the answer becomes `finalTargetX: 1` and `rejects` is still false.
