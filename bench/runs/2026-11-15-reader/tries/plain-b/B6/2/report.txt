A degenerate up (parallel to the line of sight, either direction) leaves the roll unchanged. It starts upright, using world +Y projected into the view, with +Z as a fallback for a vertical view. Throws a RangeError if eye equals target. Things to know:
- The pinned babylon-lite checkout has no `FreeCamera` class. The `FreeCamera` type is exported as an interface, and the factory is `createBankedFreeCamera`, which is the one used here. The spec's `import type { FreeCamera }` still works.
- The `tsc` run reports many errors inside babylon-lite's own sources (missing `?raw` shader module declarations, WebXR globals). They are pre-existing and do not involve the app.
- The "exactly parallel" test uses a 1e-9 threshold on the perpendicular component. Up vectors that are nearly but not exactly parallel still roll, with noisy direction as the angle approaches zero.
