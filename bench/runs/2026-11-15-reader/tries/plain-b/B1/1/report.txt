How it works: it calls the library's `attachControl(camera, canvas, scene)` for drag, wheel and pinch controls, then `setCameraLimits(camera, { lowerRadiusLimit: minDistance, upperRadiusLimit: maxDistance }, scene)`. The library enforces the range inside the `radius` setter, so wheel inertia and pinch writes are clamped in the same statement, and an out-of-range starting camera is moved in immediately. The returned function detaches the controls (canvas listeners and the `_beforeRender` inertia hook), releases the clamp hook, restores the camera's previous radius limit fields, and is safe to call twice. It throws a `RangeError` if the range is not finite, `minDistance <= 0`, or `maxDistance < minDistance`.

Verification: `npx vitest run` in the app passes all 5 tests (initial clamp, 200 frames of heavy wheel input, an extreme pinch sequence, listener and hook removal, invalid range). The tests use a fake canvas and a plain scene object, not a real browser. `tsc` reports 87 errors, all in the library's WebXR and `?raw`/worker import typings. None are in `app/src`.

Not fully sure of: I checked the clamp logic by reading the source, not in a browser, so a real-device check of wheel and pinch feel is still worth doing. I also did not add any `touch-action` CSS; the library's own pinch handling calls `preventDefault`.
