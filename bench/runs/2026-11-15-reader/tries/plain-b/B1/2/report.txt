I added `attachLimitedOrbit` in `/tmp/claude-0/-home-user/00000000-0000-0000-0000-000000000000/scratchpad/reader-work/plain-b/B1/2/app/src/limited-orbit.ts`. It wraps the library's `attachControl` (orbit, wheel, pinch, and the per-frame inertia hook) and `setCameraLimits` with `lowerRadiusLimit`/`upperRadiusLimit` set to the two distances. The library's radius setter clamps every write, so the radius stays in range on every frame, and a camera that starts outside the range is moved inside as soon as the function is called. The returned function is idempotent: it detaches the canvas listeners, removes the inertia hook, and clears the radius limits it set. I also added a vitest file at `/tmp/claude-0/-home-user/00000000-0000-0000-0000-000000000000/scratchpad/reader-work/plain-b/B1/2/app/src/limited-orbit.test.ts`; its 5 tests pass (out-of-range start, heavy wheel zoom both ways, pinch, detach cleanup, invalid input). The app's own sources type-check cleanly; the tsc errors that remain are all inside the babylon-lite checkout (missing `?raw` and WebXR typings), not in our files.

Things I was not sure of: (1) the function throws a RangeError unless `0 < minDistance <= maxDistance` and both are finite; (2) I chose to clear the radius limits on detach, so the camera is unconstrained after detach, which is my reading of "removes the controls" and can be changed; (3) the library floors the radius at 0.01 on wheel and pinch, which the setter clamp still keeps inside the range, so this is not a problem for the range itself; (4) I tested with a fake canvas and scene in node, not in a real browser, so the real pointer and touch behaviour is unverified.
