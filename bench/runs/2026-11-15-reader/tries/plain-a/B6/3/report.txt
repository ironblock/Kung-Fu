I wrote /tmp/claude-0/-home-user/00000000-0000-0000-0000-000000000000/scratchpad/reader-work/plain-a/B6/3/app/src/chase-camera.ts. It exports `createChaseCamera(eye, target)` and returns `{ camera, bank(up) }` as specified. The camera is built on `createBankedFreeCamera` from the checkout at babylon-lite, which already has a mutable `upVector`, and `bank` writes the car's normalized up into it. The look-at builder then takes the component of up perpendicular to the line of sight, which is the picture-up the spec asks for. When up is parallel to the line of sight (|up x d| below 1e-10, or a zero or NaN up), `bank` returns without writing, so the roll stays as it was.

I checked it with a temporary vitest file against the checkout: the camera starts upright, banks to the perpendicular projection, keeps its roll on parallel ups of either sign, and produces finite view matrices. The temporary test is deleted, so the only change is the one file. Typecheck shows no errors in the app's own source; the errors it reports are pre-existing ones inside babylon-lite (missing `?raw`/`?url` shader module declarations and missing WebXR types).

Not sure about two things. First, the parallel check uses the library's own 1e-10 threshold; a float32-derived up with noise above that near the line of sight will roll the camera by an arbitrary-looking amount, since that roll is ill-conditioned there. Second, if eye and target are vertically aligned, the initial upright default is itself degenerate, so the library's identity fallback applies until the first non-degenerate `bank` call.
