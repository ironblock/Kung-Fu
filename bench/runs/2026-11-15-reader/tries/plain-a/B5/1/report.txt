It builds on the checkout's own helpers (`getViewMatrix`, `getViewProjectionMatrix`, `projectWorldToScreenToRef`) and uses the canvas's backing size for the aspect ratio and CSS size for `x`/`y`. `visible` is the library's `!offscreen`, which covers in front of the camera and inside the picture, and ignores near/far depth so far-away points still count. Things I was not sure of:
- Floating-origin (LWR) cameras: I rebase the point onto the camera position whenever the camera's internal `_useFloatingOrigin` flag is set. That flag is marked `@internal` in the library, so this may break if the library renames it.
- If `camera.viewport` is set to something other than full, I ignore it, because you said the camera renders to the whole canvas.
- Edge cases: a canvas with zero backing size returns `{x: NaN, y: NaN, visible: false}`. A canvas with zero CSS size (not laid out) falls back to backing-pixel coordinates.
- Points between the camera and the near plane that lie inside the picture are reported as visible.
