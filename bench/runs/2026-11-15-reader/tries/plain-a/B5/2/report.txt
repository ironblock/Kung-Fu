It exports `labelPosition(camera, canvas, point)` with the signature you asked for. It wraps the library's own `projectWorldToScreenToRef` (from `@babylonjs/lite`, at the checkout you specified) and uses `getViewMatrix` / `getViewProjectionMatrix` for the aspect ratio of the canvas backing store. `x`/`y` are CSS pixels from the canvas top-left, using `getBoundingClientRect()` for the CSS size, as the library's own integration code does. `visible` is `!offscreen`, so it is true only for points in front of the camera and inside the picture, with no far-plane check. Under floating origin (`camera._useFloatingOrigin`) it passes the camera position as `worldOrigin`.

Things I was not sure of:
- I ignore `camera.viewport`, following your statement that the camera renders to the whole canvas. If a camera ever has a non-full viewport, the result will be wrong.
- If the canvas has no layout (zero CSS size), I fall back to one CSS pixel per backing pixel. If the backing store is zero-sized, the function returns `{x:0, y:0, visible:false}` instead of throwing.
- A camera with `farPlane = Infinity` makes the library's own projection matrix contain NaN, so every point comes back not visible. I did not work around this, since the library does not produce that configuration itself.
