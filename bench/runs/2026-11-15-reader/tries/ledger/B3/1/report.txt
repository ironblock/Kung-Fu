Things I was not sure of:
- The app is left-handed. The library picks its handedness from the babylon-lite-rh import condition, and this app does not set it. The controls copy the left-handed signs, so they would be wrong under an RH build.
- The ledger header says Babylon Lite 1.39.0, but the checkout's packages/babylon-lite/package.json says version 0.1.0. I did not check which release the checkout actually is.
- I did not re-run the ledger's ast-grep rows. My code only relies on fields that I read directly in free-camera.ts and free-camera-controls.ts.
- Call the disposer between frames, not from inside another frame callback. The scene walks its hook list with for-of, so removing a hook that runs earlier than the current one can skip the next hook that frame. The ledger's "fly: removal" note describes the same risk.
- Like the library, the controls read _yaw and _pitch as the view authority. Setting camera.target by hand while the controls are attached makes the view jump back, as the ledger's "yaw and pitch go stale" row warns.
- Key handling needs the canvas to have focus. I set tabIndex=0 when the canvas has no tabindex attribute, and cleanup removes it again in that case.
