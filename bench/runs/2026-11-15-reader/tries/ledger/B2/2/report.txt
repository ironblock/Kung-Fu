I wrote /tmp/claude-0/-home-user/00000000-0000-0000-0000-000000000000/scratchpad/reader-work/ledger/B2/2/app/src/fast-orbit.ts. It exports `attachFastOrbit(camera, canvas, scene)` with the signature you asked for. It calls the library's `attachControl(camera, canvas, scene)` and halves `camera.angularSensibility` before attaching, so the drag divisor is halved and each drag turns the camera twice as far, with the glide scaled the same way. The returned function detaches the controls and restores the original sensibility unless the caller changed it in the meantime. It is idempotent.

How I checked it: I read `src/camera/arc-rotate-controls.ts` in the checkout directly, and I did not rely on any ledger `is` note. The drag path is `inertialAlphaOffset -= dx / angularSensibility`, read live on each move, and the glide decays those same offsets. I ran a throwaway vitest against a fake canvas and scene (not kept). It confirmed that drag and glide are exactly 2x the library default, the wheel zoom is unchanged, the per-frame hook and all canvas listeners are removed on detach, and a user-changed sensibility survives detach. I deleted that test file afterwards. `tsc` reports no errors in the new file; the errors it does print are pre-existing WebXR type gaps inside the library.

Things I was not sure of:
- "Twice the default" is taken as twice the camera's `angularSensibility` at attach time (the library default is 1000). If the caller changes sensibility while attached, I leave their value in place and do not double it.
- Touch drags also go through the same handler, so they are doubled too. Keyboard arrows are not attached by this function and use their own sensitivity.
- The ledger's `count` rows are checked by a tool, but I did not run them; my conclusions come from reading the code.
