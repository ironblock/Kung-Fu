It exports attachLimitedOrbit(camera, canvas, scene, minDistance, maxDistance). It calls the library's setCameraLimits with lowerRadiusLimit and upperRadiusLimit, then attachControl(camera, canvas, scene). Every radius write runs the clamp in the radius setter, so the radius stays in range at each frame, including on the first frame. If the camera starts outside the range, setCameraLimits clamps it at call time. Invalid ranges throw RangeError. The returned function detaches the canvas listeners and the frame hook, removes the clamp, and restores the camera's previous radius limits. It is safe to call twice.

Things I'm not sure of:
- Calling the disposer from inside a frame callback can skip the next callback that frame, because the library splices its hook out of the frame list. The ledger's "fly: removal" note describes this hazard. The disposer should run outside the frame loop.
- On dispose I restore the previous radius limits, which is my choice. If you want the range to stay after dispose, remove the restore lines.
- A wheelPrecision of 0 would make the wheel offset NaN, and the radius clamp would not catch NaN. The default of 3 is fine. I did not guard against it.
- Only the radius is limited. Alpha and beta are unrestricted.
