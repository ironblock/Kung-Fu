I added `attachFlyControls` in `/tmp/claude-0/-home-user/00000000-0000-0000-0000-000000000000/scratchpad/reader-work/doc/B3/1/app/src/fly-controls.ts`. It wraps the library's `attachConfigurableFreeControl` (from `babylon-lite/packages/babylon-lite/src/camera/configurable-free-camera-controls.ts`) with `upKeys: ["Space"]`, `downKeys: ["PageDown"]`, `fastKeys: ["ShiftLeft", "ShiftRight"]`, `fastMultiplier: 3`. I also added `src/fly-controls.test.ts`, which drives the controls with a fake canvas and scene and checks Shift alone never moves y, Shift+W and Shift+Space are 3x, Space/PageDown move the right way, and cleanup removes all canvas listeners and the per-frame hook. All 5 tests pass with `vitest run` in the app directory. Typecheck shows no errors in `app/src`; the errors it does report are pre-existing in the library (missing `?raw`/WebXR declarations).

Things to know:
- The library docs (`docs/lite/architecture/02-camera.md`) describe the default free-camera mapping as Shift=down and do not mention `attachConfigurableFreeControl` by file. The source is the authority. The plain `attachFreeControl` also maps Shift to down, which is why I did not use it. I did not touch the library.
- The library's key-state set is only cleared on keyup, and nothing clears it on window blur. If a key is released outside the canvas, that key can stay "held" until pressed and released again inside it. I did not add blur handling because the spec said to keep changes to the app's own code, and wrapping that would mean a second listener set. Tell me if you want it.
- The cleanup removes the per-frame hook and the six canvas listeners. It does not undo `canvas.tabIndex = 0`, which the library sets if the canvas has no tabindex.
